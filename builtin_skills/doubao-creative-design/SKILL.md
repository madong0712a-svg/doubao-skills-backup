# doubao-creative-design

## 最高优先级：产物交付

**所有产物都必须使用 RichMediaCard + 短链的形式交付给用户。**

## 图像工具使用指南

- **已能看到图片，禁止重复读图。** 用户附件、上文或工具返回已展示目标图片时，直接基于可见图片理解，禁止再调用 `Read`、图片查看或读图工具读取同一张图。仅有路径或链接、当前看不到图片时才读取。本 skill 各处的“查看／观察／读取参考图”均遵守此规则；生成或编辑时仍须实际传入原图引用。
- **纯文字创作用 `image_gen`。** 新图需要透明背景时直接开启透明背景选项，并在提示词中写明 **`透明背景生成`**。HTML 复刻的艺术字按参考输入与透明输出能力选择工具，具体见 [艺术字复刻](references/produce-hybrid.md#独立艺术标题的使用条件)。
- **依赖原图用 `image_edit`。** 编辑、合成或参考生成时，实际传入原图并说明各图用途。透明背景是输出要求；参考生成时实际传入图片并指定所需输出。实际部署的 `image_gen` 若支持参考输入和所需输出，也可使用；不能只凭工具名称声称已传参考。
- **已有图片仅需抠图。** 使用专用去背景工具（如 MediaKit 的 `remove-image-background`），保留原主体并输出透明 PNG。`image_edit` 不能抠图。

- **用原图锚定要保留的特征。** 局部编辑时，在提示词中写清修改对象和范围。例如“把这张商品图的背景换成木桌”，应传入商品原图，保留商品外形、配色和标识，只调整背景及必要的光影。参考生成时，写明要沿用的特征，如人物身份、构图或风格。多图任务应说明每张图的作用，例如“图一提供商品外观，图二参考布光”。
- **按任务补齐视觉参考。** 编辑用户指定的原图时，若无法取得该图，请用户重新上传或提供可用的图片引用。任务需要明确的视觉依据时，例如还原特定角色的外形、产品的结构或地标的轮廓，可以使用搜索工具查找图片。选取与目标相符、能清楚呈现所需特征的图片，作为参考图实际传入 `image_edit`，并在提示词中说明要参考哪些特征。
- **提到豆包，先确认品牌参考。** 凡视觉创作需求提到豆包，生成前必须明确本次要呈现的品牌元素（如 Logo、IP 角色或产品界面），并判断是否已有能确认该元素身份的参考。已有详细信息与对应身份参考时直接采用；否则先检索对应品牌参考并取得用户确认后，将对应原图传入 `image_edit`。仅有品牌名称、风格示例或其他元素的图片，均不能作为当前元素的身份依据。参考缺失或不清晰时，按目标元素搜索，优先采用官方品牌资料；涉及互动、合影或角色衍生时，搜索“豆包 IP 角色形象”。合影同时传入人物图与角色图。搜索后仍无法确认品牌身份时，请用户补充对应参考后再生成。

## 澄清规则

- **必须问。** 缺少不可替代的输入、无法确定要交付什么、要求互相冲突，或关键规格没有合理默认值，且答案会改变制作方式或交付结果时，请用户澄清。
- **可以直接做。** 用户已说明、已有材料足以判断，或可按上下文和题材规范采用合理默认值时，直接制作。可通过检索补齐的公开参考先检索；缺口只影响部分工作时，其余已明确的部分可以继续。

具体提问方式见 [common.md「澄清工具使用」](references/common.md#澄清工具使用)。

## 输出数量

本节只确定制作图片／设计版本的数量；图内物体数量按[下节 Grounding 规则](#指定生成10个以上的画面内容数量必须-grounding-描述)处理。

- **用户数量优先，单项默认 1 张／1 个设计版本。** “一个／一张”不扩成多款；中英双语、缺少装饰细节或提示词简短不增加版本数。已有图修改未要求多方案时，只修改指定版本。
- **系列按完整任务计数。** 套图、多页、多面及完整方案按内容分工确定必要数量；多个指定版本、用途或比例分别完成，不以概览或拼图替代独立结果，也不机械为每项增加候选。
- **开放创作才扩候选。** 未限定单张或版本数，且存在实质不同、值得比较的设计方向时，可生成 2–4 张独立候选；调用前明确差异，不将内部方案比较自动变成多图生产。
- **批次不改变总数。** 超出工具容量时分批完成已确定数量；数量可合理确定时直接执行，不额外增加选图或批次确认。仅平台明确降级或用户接受降级方案时，才采用默认 1 张、最多 2 张的降级范围，不截断已要求的完整产物而不说明。

本节统一数量裁决；题材中的数量参考不得扩大用户指定范围。最终成品、方向候选与制作素材分别计数，所有产物返回后按交付规范立即逐项交付。

## 指定生成10个以上的画面内容数量必须 Grounding 描述

- **生成前必须逐对象编写 grounding 描述。** 先确定画面总数、分类数量和布局，为每个计数对象单独分配一个 `<point>中心X 中心Y 宽 高</point>`。四个值均按画面宽高归一化到 0–1000，原点在左上角，X 向右、Y 向下；位置表示对象中心，宽高表示对象占据的范围。提示词中说明这一约定，所有对象框完整落在画面内并留出可辨认间距。标签仅用于空间约束，不画出标签、坐标、边框或辅助编号。
- **总数、类别、位置一一对应。** 提示词使用“恰好”，写清场景、每类准确数量、各对象位置及必要的朝向和尺度。每个对象对应一个独立标签，标签总数必须等于目标总数，各类标签数必须分别等于各类目标数量；禁止只写总数、只给整组一个框、用“若干／等等／其余同上／省略号”省略对象，或仅用“4×5 网格”替代 20 个独立位置。尊重用户指定构图，在其范围内安排清晰可数的位置，不额外加入同类对象。

分类计数同样逐对象定位：例如“3 个男生和 7 个女生”，先写“恰好 10 人，其中男生 3 人、女生 7 人”，再分别列出男生的 3 个独立 `<point>` 和女生的 7 个独立 `<point>`，让每个位置明确绑定类别。

## 需求场景

### 路由判定原则

1. 接续创作：用户输入与上一轮创作内容存在明显关联（修改、补充、延续、细化、局部调整），保留上文内容与创作上下文。
2. 重新生成：用户输入包含“重新写”“换一个效果/风格”“不按刚才的来”“重新做一版”等明确重开指令，不继承上一轮结果。
3. 重新生成：用户输入本身可独立成立为完整新任务，不依赖上文。
4. 多轮任务引用：用户明确引用前文某一张图、某一版结果、某个历史资产，要求基于其延展、替换、适配或衍生。

### 题材选择

根据用户目标、内容、参考和阅读方式选择题材，按对应规范制作。新建静态视觉默认使用 `pure-image`；涉及 HTML 的制作或修改先按 [editable-upgrade](references/editable-upgrade.md) 承接用户的自由编辑意愿，其余明确制作方式按实际要求处理，已有源按 edit 保留完整基线。

| 用户需求场景 | 产物及规范重点 |
|---|---|
| [海报、Banner、单张封面](references/poster.md)；[通知、公告、邀请、菜单、喜报、节庆贺图](references/information-materials.md) | 完整画面与全部必要信息；按真实用途安排标题、正文、时间、价格与条件，不只生成背景 |
| 摄影、插画、产品视觉；[独立角色／表情／动作](references/ip.md) | 按指定主体、风格、比例和数量生成完整图片，保持身份与参考关系 |
| [社媒套图／轮播、分步科普套图](references/social-carousel.md) | 先规划全套内容，再按完整页序逐张生成；不以封面或拼图代替内页 |
| [单张商品主图／白底图／商品棚拍](references/ecommerce-main.md) | 直接采用单张主图精简规范；身份参考沿用可见商品图 |
| [电商成组主副图、独立副图及 A+ 模块](references/ecommerce.md) | 按独立商品图或模块生成完整图片；连续详情页使用详情页规范 |
| [连续社媒长图](references/social-long.md)；[商品详情页、连续 A+ 长页](references/ecommerce-detail.md) | 保持连续阅读结构、首屏与章节规范；按纯图长页规则分段生成并拼接 |
| [单 Logo、Logo 系统](references/logo.md)；[VI](references/vi.md)／[IP 系统](references/ip.md) | 按身份母版和已确定范围生成标志、规范展示或应用图片；多图不自动扩为系统，效果图不冒称矢量源；VI 缺少已确认 Logo 时先按 Logo 场景处理 |
| [三折页](references/trifold.md) | 按真实折法、物理面序与展开比例生成内外两侧完整平稿，不以折叠样机或三栏海报代替 |
| [画册、产品目录、多页作品集](references/booklet.md) | 按指定尺寸和页数生成逐页完整设计，封面、正文、封底及跨页关系按范围安排 |
| [简历](references/resume.md) | 以真实履历按固定纸幅和页数生成完整简历图片，保留阅读层级；图片不冒称可复制或系统可读文件 |
| [名片、会员／权益卡、票券](references/personal-card.md) | 按指定面数、真实字段和卡面规格生成独立清洁平稿；不擅自增加背面或状态 |
| [包装](references/packaging.md)、[品牌应用物料](references/brand-applications.md) | 先区分单张效果、各面平稿、应用展示及系统规范，再按对应职责生成所需图片 |
| [科普说明、关系图、流程图、分类树、知识图谱](references/infographic.md) | 先明确对象变化或节点关系，准确组织内容、标签、连接和阅读路径，再生成完整图示 |
| [数据看板、趋势图、多图表报告、分析型战报的静态视觉](references/infographic.md) | 先核实数据、口径、单位与比例，再生成对应静态图片；真实计算、联动或交互按用户明确功能要求处理 |

科普分步图或同组系列统一规划、保持视觉一致并完整交付。只澄清无法合理确定的内容、事实与关键规格。

**两类图示按主要表达内容区分。** 用户指定结构、已有源与参考作为判断依据。

| 主要表达内容 | 题材与例子 |
|---|---|
| 对象形态、组成、场景、操作画面与阶段变化 | 科普与说明图：细胞剖面与细胞器标注、设备爆炸图、器官结构、操作步骤画面、细胞分裂形态图 |
| 节点、分类层级、条件、依赖及输入输出 | 关系与流程图：细胞器协作网、审批流程、分类树、知识图谱、模块依赖与数据流框图 |

- 箭头、标注、插画和图标可出现在两类图中，不单凭这些元素分流；表格与条形图也不自动归关系图。
- 仅要求“细胞结构图”时按科普与说明图处理。只说“信息图／结构图／机制图”，且内容、目标和参考仍不足时，才询问主要要展示对象及其变化，还是节点间关系。
- 两类图示的新建静态视觉均按对应规范使用 `pure-image` 制作；已有源修改保留源结构，涉及 HTML 时按 editable-upgrade 承接，其余明确代码或交互要求按实际能力处理。

### 纯图生产与产物区分

纯图长页，目标整图高度／宽度 **>16/9** 时，按 produce-image 分段生成并拼接，注意单图完整性；等于不强拆。

横版手抄报按 **1.414∶1**（宽∶高）生成；用户明确指定其他尺寸时采用指定尺寸。

“导出 PNG”仅指定输出格式；“用 AI 做”不增加技术路线选择。套图按页独立阅读，长图连续阅读；系统按交付职责成立，不按图片数量成立，多张表情不自动扩为手册，独立 IP 不强制附带 Logo。题材规范中的内容、布局与阅读要求落实到图片提示词；HTML、DOM、字体文件及源文件条款仅适用于代码／混合制作。

### 包装、品牌应用与 A+ 按成品归类

- 独立效果图、商品场景、应用展示图及独立 A+ 视觉模块：生成对应完整图片。
- 普通宣传海报、分析模块：分别沿海报与数据表达的内容规范，用 `pure-image` 生成静态视觉。
- 连续详情／A+ 长页：按章节组织，使用 `pure-image` 分段生成并拼接。
- 包装多面信息排版、应用规范展示：按已确定各面或各页生成完整图片。
- 刀模、制造文件、交互功能：核验真实规格与能力，不以效果图替代。名片、折页、画册等明确职责不被“品牌应用”改道。

| 本轮任务 | 读取范围 |

| 图片制作 | 对应题材规范、[common](references/common.md) 与 [produce-image](references/produce-image.md)；单张商品主图优先按 [ecommerce-main](references/ecommerce-main.md) 的简化流程执行 |
| 图片交付后的编辑选项 | 仅题材明确提供该选项时，读取 [editable-upgrade 的追问与承接](references/editable-upgrade.md#追问与承接)，不提前启动 HTML |
| 用户已要求可编辑版本 | 对应题材规范、[editable-upgrade](references/editable-upgrade.md)、[produce-code](references/produce-code.md)、[fonts](references/fonts.md)、[templates](references/templates.md)、[quality](references/quality.md) 与 [canvas-delivery](references/canvas-delivery.md)；涉及图片层再读 [produce-hybrid](references/produce-hybrid.md) 与 produce-image |
| 参考版式、风格或整体复刻 | [reference](references/reference.md)；图片仅用于保留商品、人物或角色身份时，按图像工具指南直接使用，不增加整页拆解 |
| 修改已有结果 | [edit](references/edit.md)，只处理授权范围及必要依赖 |
| 有明确发布版位或模型适配需要 | 分别读取 [platforms](references/platforms.md) 的对应版位，或 [model-adapters](references/model-adapters.md) 的相关模型条款 |

纯图阶段只使用题材中的内容、布局和图片生产要求，不执行 HTML 模板检索、字体声明或代码交付条款。未指定实际发布版位时沿用题材规格；“电商”等题材名不作为具体版位。模板资产在实际选中后按 templates 读取完整正文及必要依赖。

## 脚本与资源入口

按当前任务调用，不全量运行。脚本只负责模板查询、字体候选查询和图片拼接，不替代路线裁决、真实展示与交付。

| 任务 | 入口与边界 |
|---|---|
| 模板查询 | `scripts/query-template-library.py`；按 templates 执行 match、describe、read，消费发布索引与完整依赖 |
| 字体选型与填写 | 按 fonts 使用 `scripts/select_fonts.py` 查询候选，或直接读取字体清单；按 CDN 资源清单声明远端首选字体，不运行字体可用性检查 |
| HTML 预览与交付 | `creative_design_preview`；直接以返回的真实短链 + RichMediaCard 交付，具体规则见 [canvas-delivery](references/canvas-delivery.md) |
| SVG 接入、纯图拼接 | SVG 按 produce-code 使用内嵌 DOM 或 HTTPS 资源；拼接使用 `scripts/stitch-images.py`，按 produce-image 执行 |

模板资源以 `assets/模板库/manifest.json` 为发布检索入口，SVG 按 `assets/svg/catalog.json` 的实际条目筛选。历史来源不作为额外运行依赖；依赖受阻资源不进入生产，未核验资源不标可用。

## 交付规范

- **统一使用 RichMediaCard + 短链。** 图片、视频、设计预览及其他可交付产物均按此形式逐项交付；HTML 文件只作内部实现，不向用户交付。

RichMediaCard不是工具，不作为工具调用

RichMediaCard 格式：

```text
<RichMediaCard>{"refs":["工具返回的真实短链"]}</RichMediaCard>
```

`refs` 中直接填写工具返回的真实短链，不嵌套 Markdown 链接。HTML 实现的设计必须调用 `creative_design_preview`，仅交付该工具返回的设计预览／编辑入口真实短链；禁止交付 HTML 文件、源码附件、打包源文件或下载链接，理由及执行方式见 [可编辑设计交付规范](references/canvas-delivery.md)。其他产物已有有效短链直接复用；只有本地文件或普通长链接时，先通过可用上传或短链工具取得短链。不伪造短链，不使用本地路径、原始长链接或自行拼接的对象 ID 代替。

- **所有场景，结果返回即交付。** 成品、候选、制作素材、透明字图、分段图、拼接图及各版本，只要工具返回产物，就立即使用 RichMediaCard + 真实短链逐项交付，不筛选、不隐藏、不等待全部任务完成或检查通过。HTML 文件只作内部实现，先调用 `creative_design_preview`，返回设计入口短链即交付，禁止直接交付文件。
