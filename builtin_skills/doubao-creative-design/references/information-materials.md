# 通知、邀请、菜单与信息物料

**读取方式**：按主入口的任务与阶段指引直接读取本文件；已有内容沿用，仅补读当前任务需要的关联规范。纯图阶段不执行 HTML 专属条款，模板资产仅在实际选中后读取完整正文及必要依赖。

**结果处理（所有场景）**：所有产物返回即按[主入口](../SKILL.md#交付规范)用 RichMediaCard + 真实短链交付；HTML 仅交付 `creative_design_preview` 的设计预览／编辑入口短链，不交付源文件。非 HTML 产物一律不做产物校验，包括混合素材和拼接结果。HTML 可检查，但检查不延后交付；只有符合 [quality 单轮溢出例外](quality.md#内容溢出允许增长长度的有限例外)的 HTML 可自主增长长度，同一任务最多一轮。该例外优先于本文件中只记录、不自主改高或重排的一般限制；除此之外，必须用户明确说改才改。不得因效果不好自主重生、修图、替换或重排。继续完成原定未完成产物和首次预览，不擅自增加优化轮次。

适用于以事项、安排、条目或祝贺信息为主的通知、公告、邀请函、名单、菜单、喜报及节庆贺图。品牌与活动宣传按 [poster](poster.md)，以数据分析为主的报告按 [infographic](infographic.md)；按实际表达任务选取，不因横竖比例改变题材。

## 内容与制作

- 用 pure-image 生成包含准确文案与完整排版的图片。文案、事实、参考与数量按 [common](common.md) 和 [主入口](../SKILL.md)；具体调用与图内文字按 [produce-image](produce-image.md)。
- 通知、公告与邀请：明确事项、对象、时间、地点、行动方式与必要条件；原文已给定时保留，不补造联系方式或活动安排。
- 菜单与名单：按真实栏目组织条目，名称、价格、单位及备注逐项对应；保留用户给定排序和分组，不为排版改价格、漏条目或编造品项。
- 喜报、成果发布与节庆贺图：保留真实主体、成果、日期或祝福语，突出主信息；装饰不暗示未经核实的荣誉、业绩或机构背书。
- 按指定尺寸与阅读距离安排层级，信息较多时先分组并核对容量；多页任务先规划完整页序，再逐页生成。光效、放射、文字净空及背景限制沿用 common 与 produce-image。

## 交付

每张完整图片返回后立即交付，标明必要的页序或版位，不以无字底图或局部细节代替成稿。图片展示与数量要求按主入口执行。

### 图片交付后的编辑选项

仅以下题材在交齐本次图片后，按实际类型选用一句编辑建议，不向用户列出所有类别：

- 信息主导的通知、邀请函及公告：“需要可自由编辑的设计吗？你可以修改文案、时间地点并调整排版。”
- 菜单、名单：“需要可自由编辑的版本吗？你可以更新条目、价格或备注，并调整栏目排版。”只提本次确实存在的字段。
- 喜报、成果发布、节庆贺图：“需要可自由编辑的设计吗？你可以修改标题、成果或祝福文字，替换图片并调整排版。”

提问时机、已有意愿处理及同意后的制作见[追问与承接](editable-upgrade.md#追问与承接)，同一任务不重复追问。
