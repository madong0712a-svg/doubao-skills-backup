# 食堂采购清单处理 SOP（每周五复用）

> 适用：微信收到手写采购清单 → 做成待审核表交用户核对 → 定稿后录入微信小程序采购申请并提交。
> 模板目录：`C:\Users\madong\Doubao\chats\purchase-template\`

## 一、固定业务信息（每次默认沿用，无需再问）

| 项 | 值 / 规则 |
|---|---|
| 采购餐厅 | 合阳县新池镇中学（小程序自动带出） |
| 供应商 | 供应商列表**第一项**：合阳县腾婷青菜干菜店 |
| 联系电话 | 系统自动带出，**不手动填写、不修改** |
| 清单来源 | 微信聊天对象「黑池彤彤」发来的手写清单图 |
| 计量单位 | 斤 |
| 存疑处理 | 看不清的品名/数量/单价**不臆造**，标注「待核对」一次性列给用户确认 |

## 二、标准流程（6 步）

> **顺序闸门**：先识别清单 → 交用户检查审核定稿 → 最后才录入小程序。用户未审核定稿前，不打开/操作小程序，不提前下单。

### 第 1 步：取图、预处理、放大辨认
1. 在微信对话中把清单原图另存到当天工作目录。
2. 跑预处理脚本分段放大并增强字迹：
   ```
   python preprocess_qd.py <原图路径> <输出目录> 2
   ```
   产出全图、上下两段放大图及灰度/对比度/锐化增强版，逐行辨认品名、数量、单价。
3. **数量优先复核**（历次最高频错误）：先查小数点是否错位，再查末尾 0、十位数字是否漏读；数字形近（5↔9、1↔7、0↔6）二次放大核对。
4. **品名不先入为主**：潦草字不要硬套常见菜名；对照词库 `ingredients_dict.json` 匹配，未收录或存疑的标「待核对」，不要猜。三类最易混，放大后重点辨：
   - **叶菜类**：青菜 / 韭菜 / 蒜苗 / 青笋；
   - **根茎类**：白萝卜 / 红萝卜 / 花白 / 白菜；
   - **小果类**：圣女果 / 苹果 / 橘子 / 橙子。
5. 整行涂黑/缺字的行标「待补充」，留待用户确认，不臆造。
6. 辨认规律与历次误判对见 `识别复盘记录.md`，新误判定稿后回填。

### 第 2 步：生成待审核 Word 表（脚本一键出多单 docx）
1. 复制 `qd_data.example.json` 为当天数据 JSON，填入 `title`、`output_dir`、`restaurant`、`supplier`、`sheets`（每单一个 `{date, rows:[{name/qty/price/note}]}`）。
2. **先跑自检**，按提示复核品名、单价区间、小数点和分单/总计合计：
   ```
   python check_qd.py <数据.json>
   ```
   脚本兼容旧单 `rows` 与多单 `sheets` 两种结构；定稿后可在 `grand` 填对照值，脚本自动勾稽总计。
3. 运行生成 Word 多表：
   ```
   python make_qd_word.py <数据.json>
   ```
   产出《title（待审核）.docx》，每单一表、自动算金额与合计，备注非空的行自动汇总到文末「待核对事项」。
4. 把 docx 交用户在本地/Canvas 内逐项核对；用户改完品名/数量/单价后，**回读最新文档数据**作为录入依据，不凭记忆。
5. 单张旧表如需 xlsx，可用 `make_qd.py`（仅支持单 `rows`）。

### 第 3 步：新建小程序采购申请
1. 小程序历史采购单页 → 左上角返回首页 → 点「采购申请」。
2. 收货时间选当天清单对应日期（年/月默认，只点日再确认）。
3. 供应商点开列表，选**第一项**；电话自动带出，不动。

### 第 4 步：逐项添加食材并填数量
对清单每一行：
1. 先查 `识别复盘记录.md` 第七节「小程序档案品名映射」，清单写法与档案名不一致的按映射选档。
2. 「添加食材」→ 顶部搜索框输入品名 → 点右侧蓝色 **+** 加入。
3. 点数量框 → 弹窗「请输入数量」→ `Ctrl+A` 清空 → 输入数量（可含小数）→ 确定。
4. 档案单价与清单价一致的直接保留；不一致的先按系统价加入，留到第 5 步统一改。

### 第 5 步：回明细表按清单价改单价
1. 全部加完后回明细表，按「品名 + 数量 + 单价」逐行核对（明细排列顺序与清单序号不同，勿按行号对）。
2. 单价不符的行：点单价框 → `Ctrl+A` 全选 → 输入清单单价 → 回车（明细单价直接编辑，不弹对话框）。
3. 改完核对底部：总斤数、总金额与审核表合计一致。

### 第 6 步：提交并核验
1. 点「提交采购申请」→ 等待「提交中…」结束。
2. 回到历史采购单列表，核验新单：商品种类数、总金额、状态「待接单」、供应商、收货日期。
3. 确认无重复单据后结束；把单号、种数、总金额回报给用户。

## 三、工具坑（已验证，避免重踩）

- **GUI 操作前必须先有一次截图**，否则指针操作报 `CU_INVALID_ACTION`。
- 滚动：`cu.scroll(x, y, "up"/"down")`，正数向上、负数向下；无 `amount=` 关键字。
- 偶发 `CU_USER_INTERRUPTED` / 图片上传失败：等 2 秒重新 `cu.screenshot()`，以新帧为准。
- 食材搜索/加入/填数量：数量走弹窗；明细单价是直接点击编辑，不弹窗。
- lark-cli（Windows）：先 `cd` 到工作目录；`--file`/`--output-path` 只接受 CWD 内相对路径（`./xxx`）；中文/复合 JSON 先落文件再 `@文件` 传入，禁止内联。
- 环境为 main 桌面（登录态在 main），CU 操作 `plane="cu"`，先 `cu.switch_desktop("main")`。

## 四、提速清单（下次照此执行）

1. **减少截图轮次**：只在三个节点截图核对——① 食材全部加完看斤数合计；② 单价全部改完看明细；③ 提交前看底部金额。中间录入动作连续执行，不逐样截图、不逐步请示。
2. **批量准备数据**：录入前把审核表整理成「品名 / 数量 / 清单单价 / 档案单价」对照，改价项提前标出，录入时照表走。
3. **搜索即匹配**：输入品名后首条即匹配就直接 `+`，不等列表完全渲染；数量弹窗 `Ctrl+A` 后直接输数字回车。
4. **改价集中处理**：不要加一样改一样；全部加完回明细表一次性改完，减少页面来回切换。
5. **存疑项一次问清**：辨认阶段把所有看不清的行合并成一条清单问用户，避免来回打断。
6. **脚本替代手工制表**：待审核表一律走 `make_qd.py`，不再逐格手工建表。
7. **留意批量入口**：下次录入时留意小程序是否有「批量导入/粘贴/追加食材」入口；若有，优先用批量方式，可显著提速。

## 五、验收标准

- 明细行数 = 审核表样数；总斤数、总金额与审核表合计一致。
- 每行品名、数量、单价与审核表一致；档案价不符的行已改为清单价。
- 提交后历史列表新单状态「待接单」，无重复单据。
- 不填、不改联系电话；不擅自扩大修改范围。

| `识别复盘记录.md` | 历次初识别 vs 定稿差异、错误统计、易错品名对照、小程序档案映射，定稿后回填 |
