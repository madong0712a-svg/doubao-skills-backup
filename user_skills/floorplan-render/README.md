# AI生成装修效果图（floorplan-render）

收到户型图 + 效果参考图，**一次性批量生成全屋室内效果图**，附逐图质检报告、房源营销文案、可施工性提示与合规风险提示。**v4.3 起平面俯视图为强制输出项**：每次调用交付效果图时，必须同批输出一张对应的 2D 正俯视线稿平面布置图（缺图即本次输出不完整）——标注房间整体长宽、墙体位置与厚度、功能分区与固定设施位置，尺寸单位全图统一（mm/m）并在图面标明，数值与效果图空间布局同源一致。**v4.4 起平面图版式对齐市面常规户型图**：墙体深灰填充、家具浅灰剪影图标、常规通俗符号（床/沙发/餐桌/灶台/洁具/门开启弧线/窗线）、房间名纯中文（拼音默认关闭）、家具家电尺寸数值直接压在图元上或紧邻位置（不用引线外挂），非专业用户一眼可辨识。无需逐个房间触发；平面图确认后才出效果图（v4.6 铁律：平面阶段改 JSON 只要几分钟，效果图每张付费）。**4.0 起内置两道安全闸**（上传图安全审核 + 生成前合规校验，组装完不等于能发）与**居住画像→出图硬约束**（老人/儿童/宠物/居家办公自动转为提示词硬约束：圆角家具、扶手位、收纳优先）。**4.7 起**附水电施工参考（从平面数据驱动算回路/点位/防水/材料清单）、多变体对比与每房环拍、布局确认闸（平面图确认后才出效果图）、户型库交叉校验（选填）。

## 核心能力

| 能力 | 说明 |
|---|---|
| 户型房间自动识别 | 上传户型图后主动识别全部房间，标注每个房间的**净尺寸**、窗户类型与相邻关系 |
| ⭐ 可施工性判定 | 内置最小可装尺寸对照表（厨房/卫生间/卧室/客厅），逐房间判定 ✅可行 / ⚠️紧张 / ❌不可，**不出物理上做不出的布局** |
| 一键全屋批量出图 | 默认 P0-P3 优先级全量生成：客厅 2 张 + 其余房间各 1 张，逐张串行、即时质检 |
| 风格匹配迁移 | 从参考图提取配色/材质/家具/照明氛围等 12 项可迁移属性；**只搬风格，不搬房子**。内置 5 套风格库，每套含【必须排除】项防混淆 |
| 逐图质检 | 每张图 **17 项**检查（墙体/门窗/动线/透视/材质/配色/文字/隐私/商业可用 + **平台水印 + 可施工性**） |
| ⭐ 平面俯视图（4.3 起强制输出） | 每次调用效果图必须同批交付：2D 正俯视线稿平面图，真实比例家具、四层尺寸标注 + 墙体厚度（总/房间/门窗/家具+通道/wall）、十一项工程自检（穿墙/门扇扫掠/通道净宽/越界/尺寸避让/挂接/单位与标注一致性/标注落点归属），FAIL 清零方可交付；与效果图同源（同一份布局 JSON），默认输出空间高效型 1 套，用户要对比时出 2 套。**v4.4 起市面常规版式**：深灰墙体、浅灰剪影家具、通俗图标符号、纯中文房名、家具尺寸压字（禁引线外挂，排版脚本自适应） |
| ⭐ 出图后处理 | 内置 `postprocess.py`：清理平台「AI生成」水印、修复乱码字、规范尺寸。**带水印的图不交付** |
| 预算控制 | 批次 >60 积分先播报预算；>10 间房只出核心空间，其余询问后补 |
| 效果对比 | 多风格对比、修改前后对比、同房间多机位对比 |
| ⭐ 两道安全闸（4.0 起） | **上传图安全审核 + 生成前合规校验**：提示词组装完不等于能发，调用生图前必须过合规校验；上传图含他人隐私或敏感内容直接拒绝进入流程，不识别、不总结 |
| ⭐ 居住画像→出图硬约束（4.0 起） | 声明老人/儿童/宠物/居家办公等居住画像后，自动转为写进提示词的硬约束：儿童房圆角家具、老人房预留扶手位、紧凑空间收纳优先（禁止画没有柜体的样板间）；**无画像不猜**，按通用家庭出图并标注 |
| 一致性如实分级 | L1 结构（房间/门窗/朝向）可保证、L2 家具件数多数可保证、L3 家具朝向不可靠、L4 尺寸与占墙比例做不到——**不吹"完全一致"**，尺寸一律以平面俯视图为准 |
| ⭐ 跨房 seed 一致（4.7 起） | 同户型全部镜头共用一个 seed（计划文件内容哈希派生，同户型重跑必得同值），替代竞品 designId 思路；`--seed` 可显式覆盖 |
| ⭐ 多变体与环拍（4.7 起） | `--variations N` 一次出 N 个风格版本对比（结构三锁不变只换配色材质）；`--pano` 每房东南西北 4 机位，可拼简易漫游 |
| ⭐ 水电施工参考（4.7 起） | `mep_calc.py` 从平面 JSON 驱动：回路划分/插座点位/开关点位/给排水点/防水面积/材料清单/施工说明，对齐 GB 规范体系；**设计参考口径**，正式施工图由持证单位出 |
| ⭐ 布局确认闸（4.7 起） | 平面图出图后先过确认卡（`layout_confirm.md`）再出效果图：待确认项非空 = 硬闸停下等确认，全清 = 软闸注明继续 |
| 户型库交叉校验（4.7 起，选填） | 提供城市+小区名时联网检索公开户型资料做量级校验：一致增强置信、不一致以上传图为准并列入待确认、查不到如实说明；**不自建库、不落盘、不传用户图片** |
| 房源文案 | 全屋版营销文案（一句话卖点/各空间分述/三条展示文案/社交短文案），严禁编造面积朝向采光价格 |
| 合规内建 | 不判断承重墙、不虚构精确尺寸、不冒充真实实拍、每份交付必带风险提示 |

| **⭐ 两段夹击写法** | 回归实测定稿：只写"保守布局"压不住，只写"不要X"也压不住。必须**数量词（ONE/ONLY TWO）+ CRITICAL CONSTRAINT + absolutely NO 逐项点名**。见 `buildability.md` §4 |

## 回归验证结论（3.0.1，真实数据）

以 37㎡ 户型（厨房 1.9m / 主卧 3.1m / 卫生间 1.7m 净宽）实测：

| 空间 | 加硬约束前 | 加硬约束后 |
|---|---|---|
| 厨房 | ❌ 双排橱柜 + 大玻璃窗 | ✅ 单排一字型 + 小平窗 |
| 主卧 | ❌ 1.8m 大床居中两侧留通道 | ✅ 1.35m 床靠单墙、单通道 |
| 卫生间 | ❌ 三件套含玻璃淋浴房 | ✅ 二件套 + 浴帘 |

后处理脚本同期复验：3 张全部检出平台水印 → 裁切后目视确认干净、无白边、无色带、构图无损。

## 交互模式（v4.7）

```
收到图 → [-1]上传图安全审核 → [-0.5]避坑约束加载 → [0]探测生成能力
      → 判定齐全（缺风格/户型图才问；预算>60积分要问）
      → 识别全部房间 + 可施工性判定 + 居住画像约束 → 风格迁移卡（含排除项）
      → [4.5]平面布局 JSON → draw_floorplan.py 出平面俯视图（十一项自检 FAIL=0；市面常规版式：深灰墙体/灰剪影家具/尺寸压字）
      → [5]合规校验（提示词十二段式由 make_room_prompts.py 生成，逐字复制，禁止人工转写）
      → [6]播报预算 → [6.5]布局确认闸（平面图确认后才出效果图）→ [6.6]--dry-run 出图前预审
      → 串行逐张：生成 → 五层质检17项 → 后处理（水印/尺寸）→ 归档
      → 批次交付校验（平面图在场/FAIL=0/单位与同源）→ 一次性交付全套
        + 平面俯视图 + 自检报告 + 布局数据 + 同源对照表 + 避坑提醒 + 可施工性提示 + 文案 + 风险提示
      → 按需附：水电施工参考（mep_calc.py）｜多变体对比（--variations N）｜每房四机位环拍（--pano）｜跨房同 seed
```

## 安全红线

- 户型结构优先：墙体、门窗、房间数量、朝向不可改变
- 参考图风格可迁移，户型几何不可复制
- ⭐ **可施工性优先**：不用超出净尺寸最小可装尺寸的布局
- ⭐ **效果图必须带平面俯视图**（4.3 起强制）：每次调用交付效果图时同批输出平面图，缺图即本次输出不完整；脚本报错/自检 FAIL/字体缺失走修复或整批不交付，不得只交效果图
- ⭐ **两图同源、单位统一**：平面图与效果图共用同一份布局 JSON；尺寸单位全图统一（mm/m）并在图面标明
- ⭐ **平面图按市面常规户型图版式输出**（4.4 起）：家具家电尺寸直接压在图元上或紧邻位置，不得用引线拉到图外单独标注；版式升级不得降低避坑判定与十一项自检标准
- 无可靠图纸不判断承重墙，仅表述「建议谨慎处理的结构」
- 严禁编造楼层/面积/朝向结论/采光时长/价格/学区/产权
- 严禁冒充真实房源实拍；输出必带「AI 生成示意图」风险提示
- ⭐ **未经后处理的带水印图片不得交付**

## 依赖说明

需要宿主环境提供图片生成（图生图）能力与图像读取能力，**具体工具由执行时探测决定**（不硬编码工具名与路径，避免依赖失效）。

**若宿主无图片生成能力**：自动降级为交付房间清单、风格迁移卡与全套提示词文本，**不假装已出图**。

后处理脚本需要 Python + opencv + numpy（Windows 中文路径已在脚本内处理）。

`render.py`（多服务商出图层）仅用 Python 标准库（urllib 直连各服务商 HTTP API）；`mep_calc.py`（水电参考）纯标准库无第三方依赖。
