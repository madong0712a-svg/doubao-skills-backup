# AI生成装修效果图

> **收到图就出全套。** 户型结构优先，参考风格只迁移、不复制。
> **画得出来的，必须也装得进去。** 不做施工图，但要做可施工性校验。
> **⭐ 4.3 起：效果图必须带平面图。** 每次调用输出效果图时，同批交付一张对应的 2D 正交俯视平面布置图；缺图 = 本次输出不完整。
> **4.0 起：出图之前先过两道闸** —— 上传图安全审核 + 生成前合规校验。
> 输出的是**房源空间想象示意图**，不是实测成果，不是施工图纸，不是真实房源实拍。

---

## 一、服务对象与用途边界

**服务对象**：房产经纪人、房源运营人员、个人业主、室内设计师、家居门店。

**允许用途**：房源展示与带看辅助、购房客户空间想象参考、毛坯房空间提案、营销素材与社交平台配图。

**不属于本技能职责**（遇到必须转为"空间想象示意"，不得给出专业结论）：施工图纸深化、承重墙判断、结构改造可行性、**装修报价与价格承诺**、产权/学区/抵押等交易信息核实。

## 二、核心原则（不可协商）

1. **户型结构优先**
2. **参考风格可迁移，户型结构不可复制**
3. **默认批量直出：输入齐全即出全套，不设中途确认关卡**
4. **一次只处理一个主要修改目标**
5. **错误时回退到上一版稳定结果，重新生成而非叠加修改**
6. **不确定信息必须标注，不得猜测**
7. **每张图必须逐项质检**
8. **商业交付必须包含风险提示**
9. **单张失败不阻塞整批交付，最后统一汇总缺口**
10. **可施工性优先**：宁可用保守布局，**不可画出物理上做不出的方案**
11. **出图后必须处理再交付**：平台水印与乱码字属交付事故，不得跳过
12. **⭐ 4.0 新增：先审后生** —— 上传图先过安全审核，提示词组装完成后、调用生图前必须过合规校验。**组装完不等于能发**
13. **⭐ 4.0 新增：按人出图** —— 有居住画像时，图必须反映画像约束；无画像时不猜，按通用家庭处理并标注
14. **⭐ 4.0 新增：收纳优先于摆拍** —— 紧凑空间优先保证收纳，禁止画"没有柜体的样板间"
15. **⭐ 4.1 新增：已规避的坑必须主动告知** —— 每次交付效果图必须附《避坑提醒》，说明该图规避了哪些坑、推荐做法、以及该空间的施工验收要点。**只出图不提醒，等于把错误信息交给了业主。**
16. **⭐ 4.1 新增：规范优先于经验** —— 行业经验可以加严规范，不得低于规范。凡遇"规范要求"与"经验说法"冲突，一律取规范
17. **⭐ 4.2 新增：平面图是布局锚点，不是效果图的前置广告** —— 平面俯视图严格按户型原始结构绘制（墙体、承重墙、门窗洞口零改动），家具按真实比例摆放并通过十一项工程自检；平面数据 JSON 同步作为效果图生成的布局依据。**结构不随风格漂移，也不随方案漂移**
18. **⭐ 4.2 新增：程序算数，AI 判断** —— 平面图走"多模态读图 → 结构化 JSON → 代码精确绘图"，不走文生图。凡是尺寸、净宽、碰撞、闭合，一律以脚本输出为准；AI 只负责设计判断与数据填写，**不得手改图、不得凭视觉估算写数**
19. **⭐ 4.3 新增：效果图与平面俯视图强制同批** —— 每次调用交付效果图时，必须同时输出至少一张对应的平面俯视图（2D 正俯视、无透视、线稿），**缺图即本次输出不完整**；两图同源（同一份布局 JSON），尺寸单位全图统一（mm/m）并在图面标明，平面图标注数值与效果图空间布局一致；交付前三查（在场 / FAIL 清零 / 单位与同源）不过不交付
20. **⭐ 4.4 新增：平面图按市面常规户型图版式输出** —— 墙体统一深灰填充，家具用浅灰剪影图标与常规通俗符号（床、沙发、餐桌、灶台、洁具、门开启弧线、窗线等），保证非专业用户一眼可辨识；房间名中文加拼音小字；**家具、家电尺寸数值直接标在对应图元上或其紧邻位置，不得用引线拉到图外单独标注**；排版由脚本自适应完成（显式 offset → 一行压字 → 两行压字 → 窄高旋转 90° → 紧贴图元下方避让 → 兜底），渲染端与自检端共用同一落点公式；避坑判定（落地马桶/台下盆等）不受图标简化影响
21. **⭐ 4.5.1 新增：出图耗时的大头是冷启动，不是绘图** —— 实测端到端 ~2s 中，Python 冷启动 + matplotlib 导入占 **1.27s（64%）**，真正的矢量绘图仅 48ms（6%），savefig 约 0.44s，自检 17ms。因此：出多张图（改参数试稿、多方案对比、多份数据）必须用 `render_batch.py` 单进程批量入口，逐张起独立进程等于每张都付一次冷启动税（实测 4 张 7.9s → 2.5s）。降 dpi 不是有效优化（200→72 只省 35ms 却明显掉画质）；不要引入并发（启动税吃掉收益）；不要缓存自检结果（改了数据会拿到旧报告）。
22. **⭐ 4.5.2 新增：去掉 `bbox_inches='tight'`，画布改为显式预算** —— tight 的本质是对每个 artist 求显示坐标路径再做贝塞尔裁剪求交（606 次/图），而画布范围完全可预知。新行为：画布 = 数据范围 + `CANVAS_PAD`(300mm 文字外扩余量)，axes 铺满 figure，像素密度 `TARGET_PX_PER_MM=0.0841`。实测热跑 render 段 551→413ms（-25%）。`render_figure(bbox_tight=True)` 保留旧行为作逃生口。交付前必须目视四角（图题栏/指北针/比例尺/总尺寸线）。
23. **⭐⭐ 4.6.0 铁律：平面图先行，确认后才出效果图** —— 顺序固定为：读图落 JSON → `make_room_prompts.py --check` 预检 → 出平面俯视图并交用户确认 → 用户确认后逐房间出效果图。平面图未确认，一张效果图都不许出。理由：平面图是 2 秒可改的矢量图，效果图是每张付费生成的位图；本次事故因平面图有错（次卧门位/衣柜/床位），5 张效果图全部白出再重出。
24. **⭐⭐ 4.6.0 铁律：效果图提示词必须由程序生成，禁止人工转写** —— 一律用 `make_room_prompts.py --prompt RX` 输出后逐字复制去生图。人工转写「rect 坐标 → 朝哪面墙」必然漏写、写反、凭印象补对称（本次主卧凭空多出书桌、次卧床画反、床头柜多一只）。数据层要求：`bed`/`toilet` 必须填 `head`（N/S/E/W），L 形房间的家具必须填 `against`。
25. **⭐⭐ 4.6.0 铁律：一致性分级如实标注，禁止声称完全一致** —— L1 结构（房间/门窗/朝向）可保证；L2 家具件数多数可保证；L3 家具朝向不可靠；L4 家具尺寸与占墙比例做不到（模型对百分比类约束服从度极低，5 种表述实测全败）。交付必须写「效果图为风格材质意向，家具尺寸与占墙比例以平面俯视图为准」。客户要 L4 级一致，改用建模渲染（SketchUp+Enscape / 酷家乐），文生图做不了。详见 `references/render_consistency.md`。
26. **⭐⭐ 4.6.1 新增：交付顺序按固定规则，禁止随手排** —— 结果排序固定为「客餐厅 → 卧室（主卧优先）→ 厨卫 → 阳台/玄关/走廊等附属空间」，同组内按净面积降序；未列入名单的房间排最后，同样按净面积降序。名单与排序逻辑内置于 `make_room_prompts.py` 的 `ROOM_DELIVERY_ORDER` / `delivery_rank()`，`--dry-run` 预审包第 1 节会打印本次实际顺序，交付时按该顺序呈现。**改顺序先改脚本再改本原则**，禁止口头随意排序——顺序漂移会让用户对不上批次数、对不上图。

## 五、输入契约表（4.0 新增）

**所有选填项必须带默认值** —— 用户不填也能跑通，不允许出现"待定"。

### 必填（缺一即启动澄清，不生成）

| 参数 | 说明 |
|---|---|
| **空间图** | 户型图 / 平面图 / 毛坯房照片 / 空间照片，至少一张，可辨认房间布局 |
| **风格来源** | 参考图（≥1 张）或明确的风格描述，二者其一 |

### 选填（全部有默认值）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 用途 | `通用房源展示` | 带看辅助 / 购房想象 / 社交配图 / 门店提案 |
| 居住画像 | `通用家庭，无特殊约束` | 见第八节《居住画像卡》；不提供即按通用家庭 |
| 画面比例 | `按机位默认 4:3` | 可选 1:1 / 4:3 / 3:4 / 16:9 |
| 材质偏好 | `按风格卡` | 用户指定材质时覆盖风格卡对应项 |
| 收纳要求 | `按藏八露二默认配置` | 重度收纳需求可提高柜体占比 |
| 平面图方案数 | `1 套` | ⭐ 4.3 起强制输出默认 1 套（空间高效型），与效果图批次一一对应；用户明确要"两套对比/高效vs舒适"时按 2 套（空间高效型 + 舒适体验型） |
| 目标房间 | `全屋（P0-P3）` | 用户指定时只出指定房间 |
| 预算档位 | `不参与` | **默认关闭**；仅庄主启用预算模块后生效，见第十七节 |
| 城市 | `不参与` | 仅用于物料备料量级提示，不影响出图；**配合小区名**触发户型库交叉校验（4.7 新增，选填，见 workflow.md §1.5：不自建库，公开检索现查现用，冲突时上传图优先） |

### ⭐ [-1] 上传图安全审核（4.0 新增，硬性）

**在生成能力探测之前执行。** 用户上传的图可能含他人隐私或敏感内容，本技能不替用户判断，直接拦：

| 图中内容 | 处理 |
|---|---|
| 他人证件、门牌号、电话号码等隐私信息清晰可辨 | **拒绝进入流程**，说明"图中含可识别的个人隐私信息，请裁除后重传" |

| 正常户型图/空间照片/参考图 | 通过，继续 |

**不识别、不总结、不传播与出图任务无关的任何个人信息。**

### ⭐ [5] 生成前合规校验（4.0 新增，硬性）

**提示词十二段式生成后、调用生图之前，逐条过以下红线**（任一条不满足即修改提示词，不调用）：

- [ ] 未虚构户型中不存在的房间
- [ ] 未复制参考图的空间形状/墙体/门窗几何
- [ ] 未擅自改变承重墙、外墙、承重柱
- [ ] 未新增或删除用户未确认的门窗
- [ ] 未生成未经确认的精确尺寸标注
- [ ] 未画出超出该房间净尺寸最小可装尺寸的布局
- [ ] 未含房号、姓名、电话、门牌号等隐私信息
- [ ] 未把示意图描述为真实测量图纸或专业设计成果
- [ ] 未承诺采光时长、真实面积、价格或投资收益
- [ ] 未冒充真实房源实拍
- [ ] ⭐ **避坑**：卫生间无壁挂/悬空马桶，画的是落地式（水箱、盖板、底座完整）
- [ ] ⭐ **避坑**：无岩板台面、无人造石台面、无台上盆、无岩板一体盆

### 澄清的唯三触发条件

**只有以下情况才向用户提问，其余一律直接执行：**

| 触发条件 | 提问内容 |
|---|---|
| 空间图无法辨认房间布局（严重模糊/倾斜/非户型内容） | "这张图无法辨认房间布局，请重新上传清晰的户型图或平面图" |
| 无参考图且无风格描述 | "想要什么风格？可从现代简约 / 奶油原木 / 轻奢中选，或发一张喜欢的参考图" |
| **单批次预计消耗 > 60 积分** | 播报预算并等确认："全屋 N 张预计消耗约 M 积分，是否继续？" |

**以下情况不提问、直接按降级规则处理**：

- 目标空间未指定 → 默认全屋批量
- 图片轻微倾斜/模糊但可辨认 → 继续执行，标注不确定项
- 参考图风格略有混杂 → 取主导风格，交付时注明
- 用途未说明 → 按通用房源展示处理
- **居住画像未提供 → 不问，按通用家庭出图，交付时标注"未考虑居住人群特殊需求"**
- **净尺寸未标注 → 不问，按最小可装尺寸取保守值推定，标注"需现场复核"**
- **城市/小区名未提供 → 不问**；提供了才做户型库交叉校验（workflow.md §1.5），查不到按上传图执行并如实说明

> **避坑约束加载不产生澄清（4.1）**：缺省按 `pitfall_guard.md` 默认值执行，交付时在口径声明中注明"按避坑默认值取值"。

## 七、房间自动识别与可施工性判定

对空间图至少识别：

1. **全部房间清单**（名称 + 位置 + 朝向）：客厅、餐厅、厨房、主卧、次卧、书房、卫生间、阳台等
2. 每个房间的：**净尺寸**（扣除管井后的保守值）、墙体关系、门洞、窗户（**类型：平窗/飘窗/落地窗/无窗**）、与相邻空间关系
3. 户型整体形状、入口位置、层高、主要采光面、主动线
4. 可形成房源卖点的特征
5. 无法确认的内容 → 不确定项

输出《房间识别清单》（`templates/room_inventory.md`），含**生成优先级**、**可施工性判定**，4.0 起增加**居住画像约束**与**收纳配置**两列：

| 列 | 内容 |
|---|---|
| 优先级 | P0 客厅（+第二机位）/ P1 主卧、餐厅 / P2 次卧、书房、厨房 / P3 卫生间、阳台、玄关 |
| 可施工性判定 | ✅ 可行 / ⚠️ 紧张（保守布局）/ ❌ 不可（必须改布局） |
| 居住画像约束 | 该房间因画像产生的硬约束（如"儿童房家具圆角化"） |
| 收纳配置 | 该房间柜体配置口径（如"藏八露二，玄关柜+餐边柜"） |

**默认全量生成 P0-P3。** 达到单次生成上限时：先完成优先级高的，明确报告"已完成 N 张 / 剩余 M 张"，主动询问是否继续补齐，**不得声称全部完成**。

### 可施工性判定（每房间必做）

拿到净尺寸后，对照 `references/buildability.md` 的最小可装尺寸表逐房间判定：

| 判定 | 条件 | 处理 |
|---|---|---|
| ✅ 可行 | 满足常规布局最小尺寸 | 按常规方案生成，提示词不插可施工性段 |
| ⚠️ 紧张 | 满足下限但不舒适 | **采用保守布局**，插入可施工性硬约束段，交付时标注"需现场复核" |
| ❌ 不可 | 低于下限 | **必须改布局**，插入可施工性硬约束段 + 排除项点名不可施工项 |

**关键实测数据**：

| 空间 | 最小可装尺寸 | 低于此值的错误画法 |
|---|---|---|
| 厨房 | 单排 ≥1500，双排 ≥**2400** | 双排橱柜、岛台 |
| 卫生间 | 三件套 ≥**2200** 宽 | 台盆+马桶+淋浴房同框 |
| 卧室 | 1.5m 床 ≥**3300** 宽 | 1.8m 大床、两侧留通道 |
| 客厅 | 沙发-电视 ≥2500 | 大开间大客厅 |

> **不确定净尺寸时取保守值**，不猜、不问。
> 判定为 ⚠️/❌ 的房间**必须**在提示词中插入【可施工性硬约束】段，片段模板见 `references/buildability.md` §5。

### 置信度与承重墙（硬性规则）

- 置信度 高/中/低；"低"时禁止绝对化结论，不确定项必须列入交付
- **没有可靠图纸或专业人员确认时，不得自动判断承重墙**。只能用「建议谨慎处理的结构」，禁止「可以直接拆除」「一定不是承重墙」「百分百可以改造」

## 八、居住画像（4.0 新增）

**核心认知：装修不是装好看，是装人的生活习惯。** 效果图不考虑谁住，就是营销假象。

### 《居住画像卡》

用户主动提供时按卡收集；未提供则按"通用家庭"处理并标注，**不追问、不猜测**：

```
居住画像
常住人口：□独居 □两口 □三口 □老人同住 □多孩
年龄段：  □年轻人 □中年人 □老人 □小孩
生活习惯：□爱做饭 □爱宅家 □爱收纳 □常在家办公 □爱追剧 □频繁待客
特殊需求：__________（如：婴儿房、无障碍、宠物、居家健身）
```

### 画像 → 出图硬约束映射表

| 画像信号 | 出图硬约束（写入提示词 [3] 段或房间约束） |
|---|---|
| 有小孩（0-6岁） | 儿童房家具圆角化、避免尖锐边角柜、地面材质偏软、不做通顶玻璃柜 |
| 老人同住 | 主通道 ≥900mm、卫生间画防滑地面 + 扶手位、不做地面高差、不做低照度角落 |
| 爱做饭 | 厨房按三角动线布柜（冰箱→水槽→灶台）；双排需净宽 ≥2400 否则改单排 |
| 爱收纳 | 柜体按藏八露二配置，提高柜体占比；禁止画无柜体样板间 |
| 常在家办公 | 书房/次卧画工作位（桌+椅+照明），加隔音提示 |
| 频繁待客 | 客厅保证会客区完整；餐厅餐桌按待客人数取保守大尺寸 |
| 独居/两口 | 可减少次卧数量感，但**不得删除户型图中存在的房间** |

> **画像只改家具与软装，不改户型结构。** 不得以画像为由增删房间、移动墙体门窗。

## 九、收纳配置（4.0 新增）

**原则：收纳优先于摆拍。** 业主收房后第一件事就是打柜子，画成"没有柜体的样板间"是误导。

| 原则 | 落地口径 |
|---|---|
| **藏八露二** | 柜体封闭占比约 80%，开放格/玻璃门约 20% |
| **就近收纳** | 物品就近其使用位置（清洁用品近洗衣区、餐具近餐厅） |
| **按频率分区** | 高频物品置于顺手高度，低频置于高处/深处 |
| **动线最短** | 柜体不得侵占主通道，开门幅度需留足 |

每个房间在《房间识别清单》的"收纳配置"列写出口径（如"玄关：鞋柜+挂衣区；客厅：电视柜+边柜；厨房：按动线布柜"）。紧凑空间（判定 ⚠️/❌）**优先保证收纳完整，再谈风格表现**。

## 十一、平面俯视图（2D 线稿布局图）（⭐ 4.3 起为强制输出项）

> **定位**：把户型图变成一张"放得进家具、看得清尺寸、经得起核对"的平面布置图。
> **技术路线**：多模态读图 → 结构化 JSON → `scripts/draw_floorplan.py` 精确绘图。**不走文生图** —— 比例、尺寸、闭合，文生图一条都保证不了。
> 完整规范（输入契约 / 九步流程 / 家具尺度表 / 标注规则 / **强制输出与校验机制** / 降级规则）见 `references/floorplan_2d.md`，数据 schema 见 `templates/floorplan_layout_data.md`。

### ⭐ 强制输出规则（4.3 新增，最高优先级）

**每次调用本 Skill 输出效果图时，必须同批输出至少一张与之对应的平面俯视图；缺图 = 本次输出不完整。**
俯视视图自身规范：2D 正俯视、无透视、无倾斜；清晰标注房间整体长宽尺寸、墙体位置与厚度、主要功能分区名称、家具与门窗等固定设施位置；尺寸单位全图统一（mm 或 m）并在图面标明，标注数值与效果图空间布局一致（同一份布局 JSON 同源驱动）。
双机制保障（详见 floorplan_2d.md §2.5）：**提示词约束**（平面 JSON 先行，效果图布局段引用同一数据）+ **输出校验**（交付前三查：在场 / FAIL 清零 / 单位与同源）。

### ⭐ 版式与图标规范（4.4 新增，对齐市面常规户型图）

**非专业用户一眼可辨识是第一优先。** 平面俯视图的图面表现按以下口径执行（由 `draw_floorplan.py` v4.4.0 落地，数据 schema 向后兼容，缺省行为不变）：

| 要素 | 规范 |
|---|---|
| 墙体 | 统一深灰填充（外/承重墙更深，内墙浅一档），双线墙身 + 断口体现厚度 |
| 家具图标 | 浅灰填充剪影，常规通俗符号：床（含枕头块）、沙发（含扶手靠背）、餐桌+餐椅、灶台、水槽、洁具（马桶/洗手台/淋浴间）、衣柜（含挂衣杆）、书桌、电器（冰箱/洗衣机）等 |
| 门窗符号 | 门绘开启弧线，窗用四线窗，洞口定位与宽度按数据 |
| 房间名 | **纯中文名，全图不出现拼音或中英混排**（`meta.show_pinyin=true` 才启用拼音小字，默认关闭） |
| 家具尺寸 | **数值直接压在图元上或其紧邻位置，不得用引线拉到图外单独标注**；压不下时按自适应顺序降级：显式 offset → 一行压字 → 两行压字（名称行/尺寸行）→ 窄高图元旋转 90° → 紧贴图元下方（避让其他家具与房间名/拼音/面积文字、不越出所属房间）→ 兜底；`dimensions` 的 `offset` 降级为可选微调字段，不再必填 |
| 名称去重 | 有尺寸压字的家具块内自动名让位（块内名与压字名称行不双出） |
| 分层配色 | 不同标注层用不同颜色区分，层次分明：**尺寸链** 藏青 `#1f4e79`；**房间名/面积** 深灰 `#333333`；**门窗洞口注记** 亮蓝 `#1f6fb2`；**墙体** 赭棕 `#8a5a2b`；**走廊净宽线** 青绿 `#1f7a6d`；**家具图元** 墨灰 `#2b2b2b`。窗洞图元亮蓝 `#1f6fb2`、门扇门弧赭棕 `#8a5a2b`，与墙体明显可辨 |

> 避坑判定不受图标简化影响：落地马桶、台下盆/石英石台面、推拉门形式等口径与提示词层完全一致（见 pitfall_guard.md）。

### ⭐ CAD 标注层级与尺寸线间距规范（4.5 新增，交付时必须随图说明）

平面图的尺寸标注按 CAD 制图标准分三级，图面分层绘制、层级不得交叉：

| 层级 | 内容 | 距图元/上一级的间距 | 线型与样式 |
|---|---|---|---|
| 第一层 细部尺寸 | 门窗洞口宽、墙段分格、房间开间进深 | 细部排统一外移 **1200mm** 贴图 | 45° 中粗斜短划线（`TICK_LEN=90`，全长 180mm）、文字高 `DIM_FS=6.0pt` |
| 第二层 总体尺寸 | 各边总长（如 8100 / 13000） | 在细部排基础上再外移 **260mm**（`CHAIN_TOTAL_GAP`），形成独立一排 | 同上；**必须独立成排，不得与细部排同排挤排** |
| 第三层 引注 | 墙厚、门窗洞口定位、家具压字 | 按 `offset` 就近引出，避让图形与文字 | 细实线引线 + 白底衬底防压线 |

- 标注统一置于**独立标注图层**（`zorder` 7–9，位于墙体/家具图层之上），便于整层隐藏或出图；
- **禁止**尺寸线/尺寸界线相互交叉、穿过其他标注文字、穿过图形轮廓——第 11 项自检逐条几何校验；
- 空间不足时允许断开或引出，**优先保证总体尺寸独立成排**；
- 交付时必须口头/书面说明所采用的标注层级划分与各层间距设置（即上表三行）。

### 能力边界（硬性）

1. 严格按户型图**原始结构**绘制：墙体、承重墙、门窗洞口的位置与尺寸零改动；家具只进场，不改房
2. 2D 正俯视、无透视、线稿风格，单张高清成图（**导出分辨率固定 200dpi**，屏幕按窗口自适应显示，不输出更高 dpi）
3. 家具按真实比例摆放，留足通行与开启空间，不遮挡门洞、窗户和主要动线
4. 图纸性质 = AI 布局示意图，默认**方案沟通级**；交付 JSON 数据后可声明深化设计级；**任何情况不得声明施工依据级**
5. 无可靠依据不得判定承重墙；未确认墙体按 `interior` 填写并列入待核实
6. ⭐ **强制输出**：效果图与平面俯视图同批交付，缺图即本次输出不完整；脚本报错/自检 FAIL/字体缺失等技术问题**都不是跳过平面图的理由**（唯一例外：户型图完全无法辨认，两样都不出并提示重传）
7. 尺寸单位全图统一（`meta.unit`：mm 或 m），图题栏标明；平面图标注数值与效果图空间布局同源一致

### 输入（缺一即启动澄清，不生成）

| 参数 | 必填 | 缺失时提示 |
|---|---|---|
| 户型图（jpg/png/pdf/dwg/dxf） | ✓ | "未收到户型图。请上传清晰的户型图，需能辨认房间布局与门窗位置" |
| 户型关键尺寸 | 图中标注或用户提供 | 未标注 → 保守推定 + **全部列入待核实**，不问不猜 |
| 总面积 / 装修风格 / 家庭成员与功能需求 | 选填 | 按默认值：rooms 多边形（墙中线）累加 / 现代简约 / 通用家庭 |
| 平面图方案数 | 选填，默认 `1 套` | 强制输出默认 1 套（空间高效型）与效果图一一对应；要"两套对比"时出 2 套 |
| 尺寸单位 | 选填，默认 `mm` | `mm`（整数毫米）或 `m`（米）；坐标值恒为 mm 整数，此字段只决定图面显示与标注口径 |

上传图先过**安全审核**（§六 [-1]）：含隐私/敏感内容拒绝进入流程。

### 执行流程（九步，详见 floorplan_2d.md §2）

```
[1] 核验户型资料（尺寸闭合校验；固定障碍物必须上图：烟道/燃气/上下水/地漏/检修口/强弱电箱/梁柱）
[2] 建立数据模型（按 templates/floorplan_layout_data.md 落 JSON；坐标恒 mm 整数，先定 meta.unit 显示单位）
[3] 功能需求分析（画像 → 家具硬约束，映射表见 floorplan_2d.md §2.4）
[4] 生成方案：默认 1 套空间高效型（与效果图批次对应）；用户要对比时加舒适体验型
[5] 尺寸校验（家具尺度表 + 碰撞清单 13 项 + 脚本自检 11 项）
[6] 绘制平面图（每套方案跑一次脚本，FAIL 清零才进下一步）
[7] 尺寸标注（四层 + 墙体厚度：总/房间/门窗/家具+通道/wall，JSON dimensions 驱动）
[8] 文字报告（14 节结构，含平面图↔效果图同源对照表，见 floorplan_2d.md §6）
[9] 交付（平面图 PNG + 自检报告 JSON + 布局数据 JSON + 方案说明 + 待核实清单，
        ⭐ 与效果图同批；三查不过不交付，见 floorplan_2d.md §2.5）
```

**多套方案只改 `furniture` 与家具层 `dimensions`**；`walls`/`openings`/`rooms` 原样复制 —— 结构不随方案漂移。

### 尺寸标注（四层 + 墙体厚度，不可缺层）

| 层 | 内容 | JSON kind |
|---|---|---|
| 第一层 总尺寸 | 横/纵总尺寸链（分段之和 = 总计，必须闭合） | `chain` |
| 第二层 房间尺寸 | 各房间开间×进深、墙垛/柱/壁龛、阳台走廊玄关 | `room` |
| 第三层 门窗尺寸 | 门洞宽、窗洞宽、洞口定位（定位写进文字） | `opening` |
| 第四层 家具尺寸 | 家具长宽、家具-墙/家具-家具间距、通道最小净宽、柜门抽屉范围、操作区、洁具间距；**家具/家电尺寸数值压在图元上或紧邻位置，不用引线外挂**（4.4 起） | `furniture` + `corridor` |
| 墙体厚度 | 承重墙与外墙的厚度（位置由双线墙身+断口体现） | `wall` |

单位统一按 `meta.unit`（默认毫米整数，可选米）；尺寸数字不得被图线穿过；位置紧张用引线（**家具层除外——家具尺寸一律压字，见上表与版式规范**）；**不得为画面整洁删除尺寸线**；无法确认的标"待核实"，不得编造；房间开间进深/墙厚标注数值必须与数据一致（第 7 项自检比对）；家具 `dimensions` 显式 `text` 中的「宽×深」必须与该家具图元实际宽深一致（第 7 项自检 7c 比对）。

### 十一项工程自检（draw_floorplan.py 内置，交付必附结果）

| 检查项 | FAIL 条件 | WARN 条件 |
|---|---|---|
| 家具与墙体净距 | 嵌入墙体 >0.5mm | 压墙线 ≤0.5mm |
| 门洞遮挡 | — | 门扇扫掠区（门宽半径）内有家具 |
| 家具间通道净宽 | — | 最小可通行间距 <600（老人 <900） |
| 家具房间归属 | — | 家具顶点越出房间净边界 |
| 尺寸线避让 | — | 尺寸线穿过家具图元 |
| 门窗挂接 | 门窗未挂到有效墙体 | — |
| ⭐ 单位与标注一致性（4.3 新增；4.4 加 7c） | `meta.unit` 非法；家具显式标注 text 的「宽×深」与该图元实际宽深不符（7c） | 房间开间进深/墙体厚度标注与数据不符 |
| ⭐ 标注落点归属（4.3.3 新增；4.4 随压字改制同步公式） | 家具尺寸标注（压字/offset）落点不在所属房间；房间名/面积文字压家具图块或越出本房间；房间开间标注落点越界 | 家具中心与声明房间不符；未声明 room 且几何归属不明 |
| ⭐ 标注文字防互撞（4.5 新增） | 图面任意两段文字包围盒重叠（房名/面积/六层标注/家具压字/门窗注记） | — |
| ⭐ 房间名与开间标注压墙（4.5 新增） | 房间名或开间标注压住墙体轮廓线 | 家具压字贴墙线（可接受，须目视复验） |
| ⭐ 尺寸线防交叉与穿字（4.5 新增） | 两条尺寸线相交；细部排/总排/走廊线穿过任何标注文字 | — |

**WARN 逐条写进交付检查表；FAIL 必须改数据重跑，不得带 FAIL 交付。**

> v4.3.3 起脚本 stdout 末行输出分步计时（prepare/render/selfcheck/total）与图元计数，自检报告 JSON 附 `timing` 字段——用于量化定位单次出图各环节耗时、验证优化效果。
> v4.4.0 绘图端升级为深灰墙体 + 浅灰剪影家具 + 尺寸压字 + 双语房名，单张渲染耗时与旧版基本持平（实测 300dpi 约 0.8s），版式升级不显著增加出图时间。

### 与效果图链路的衔接（⭐ 4.3 强制同源，不重复劳动）

```
平面俯视图 JSON（walls/openings/rooms/furniture，单位声明 meta.unit）
        ↓ 同一份结构数据（强制）
效果图提示词：布局段必须引用该 JSON 的家具布局与房间尺寸（模板占位符）
        ↓
效果图与平面图共用同一套结构口径 —— 图上怎么摆，效果图就怎么摆
```

- 提示词约束：平面 JSON 先落盘 → 效果图布局段引用同数据 → 提示词声明"布局与同批平面图一致，尺寸以平面图为准" → 数值与 `meta.unit` 同单位；
- 输出校验（交付前三查，详见 floorplan_2d.md §2.5）：**查一在场**（效果图与平面图 PNG 同批，缺图即输出不完整）/ **查二自检**（report FAIL=0，WARN 入检查表）/ **查三单位与同源**（unit 合法 + 图题栏单位行 + 第 7 项 PASS + 交付报告附同源对照表，房间尺寸取自 report `room_dimensions`）。

### ⭐ 布局确认闸（4.7 新增，P1-5：平面图确认后才出效果图）

**为什么**：效果图是平面图的渲染副本。平面阶段的错误（床朝向反了、卫生间塞不下淋浴）
到了效果图阶段就是 N 张图全部重出；而在平面阶段改 JSON 只要几分钟。
竞品（酷家乐等）同样把「户型确认」设为出效果图的强制前摇。

**闸门逻辑**（按 `templates/layout_confirm.md` 填写，数字全部取自布局 JSON 与自检报告）：

| 情形 | 动作 |
|---|---|
| 待确认事项为空 + 无 ⚠️/❌ 房间 | **软闸**：确认卡随流程展示，注明"无待确认项，按已确认流程继续"，直接进效果图 |
| 待确认事项非空 或 有 ⚠️/❌ 房间 | **硬闸**：停下等用户确认；用户说"按推定继续" → 逐项记录"已告知仍继续"后再放行 |
| 用户提出修改 | 改 JSON → **重跑平面图与自检** → 刷新确认卡 → 再放行（不得只改卡不改图） |
| 用户明确说"别看了直接出" | 交付报告注明"用户要求跳过布局确认"，按推定值继续（豁免仅一次） |

**铁律**：确认卡第三节（待确认事项）必须**全量**列入 `meta.pending_confirm`，
不得筛选遮掩；每一项都要给"现场找谁核实"的出口（结构图/物业/业主/设计院）。

### 降级规则

| 情况 | 处理 |
|---|---|
| 未收到户型图 | 不生成，提示上传（§输入表） |
| 图无法辨认房间布局（严重模糊/倾斜/非户型内容） | **两样都不出**："这张图无法辨认房间布局，请重新上传清晰的户型图或平面图" |
| 尺寸图中未标注 | 保守推定（floorplan_2d.md §5）+ 全部进 `meta.pending_confirm`，图题栏自动显示"待核实 N 项" |
| 用户要 CAD/矢量 | 交付 JSON + PNG，说明"本模块不输出 CAD，JSON 可按 schema 导入 CAD/酷家乐复绘"；**不得把 PNG 冒充可编辑 CAD** |
| 用户要施工依据级 / 报价 | 拒绝声明，转 §7.3 话术；报价转物料清单（不含价格） |
| ⭐ 脚本报错/环境缺依赖/字体缺失 | **不是跳过平面图的理由**：修复重跑；修不好则效果图与平面图整批不交付，如实报告，**严禁只交效果图** |
| 自检 FAIL 无法消除 | 平面图与效果图**整批不得交付**，如实报告 + "需人工复核"，不得静默交付、不得拆开只交效果图 |

## 十二、图片生成规则

### 空间一致性要求（每张图必须满足）

墙体位置基本不变；房间数量不变；门洞位置不变；窗户位置、数量、**类型与开向**不变；阳台/露台边界一致；空间朝向不变；主要动线不被家具遮挡；房间功能与户型图一致；相邻空间关系一致；**家具尺度符合该房间净尺寸**。

> ⚠ 窗户类型是批量出图的高发错误点：普通平窗不得画成落地窗或阳台门；居中房间（无外墙）不得凭空出现窗户。发现即判"重新生成"。

### 固定提示词模块（原样包含）

```
保持输入户型图的墙体位置、门洞位置、窗户位置、阳台位置、房间数量、空间朝向和主要动线不变；
仅迁移参考图的材质、配色、家具风格、照明氛围和软装元素；
正视摄影，垂直线条稳定，建筑透视合理；
真实室内摄影质感，柔和自然光，真实材质纹理；
家具尺度符合该房间的实际净尺寸，不使用超出净宽的对向高柜、岛台或大三人位沙发；
家具布置符合人体尺度，主通道畅通，不遮挡门洞；
地面、天花、墙面透视成立，家具稳定落地；
画面中不出现无法辨认的文字、错字、乱码和虚假广告；
画面中不出现房号、姓名、电话、门牌号等个人信息。
```

> ⚠️ 风险提示属于交付层，不写进生成提示词 —— 该句对渲染画面无帮助，只稀释硬约束的注意力权重。

### 排除项（生成时明确排除）

```
墙体重叠、墙体移位、门窗错位、新增门窗、新增窗户、消失门窗、户型跑偏、
空间方向改变、透视穿模、家具悬浮、家具穿模、动线堵塞、
天花无支撑结构、材质反射异常、文字乱码、虚假房源实拍、
精确尺寸标注、施工承诺、隐私信息。
```

> **紧凑空间追加排除项**：判定为 ⚠️/❌ 的房间，把该空间的具体不可施工项逐个点名追加到排除项末尾。原因：模型对"看起来高级"的大布局有强惯性，只在正向段写"保守布局"压不住。

### ⭐ 提示词结构：十二段式（4.7.0 起，由脚本生成，禁止人工转写）

> **提示词一律由 `make_room_prompts.py` 生成后逐字复制使用**（核心原则 24），
> 本节说明脚本产出的结构，供质检与排障时对照——**不是手工组装教程**。

```
[1]  场景：固定提示词模块 + 户型结构（墙体/门窗/房间数/朝向不可改变）
[2]  风格迁移（正向关键词；本风格排除项取自 prompt_templates.md §5）
[3]  机位（默认门位；--pano 时每房东南西北 4 个）
[4]  ★方位锁：关键家具贴哪面墙、朝哪（bed/toilet 必填 head，L 形房间必填 against）
[5]  ★数量锁：家具件数写死（ONE / ONLY TWO 数量词）
[6]  ★否定锁：可施工性硬约束 + 居住画像硬约束 + 避坑排除项 + 正向强化词
     （⚠️/❌ 房间或有画像时插入，必备；按 pitfall_guard.md 取）
[7]  ★平台适配层：负面提示词分平台（none/base/mid/long 四档）+ 生成参数建议，
     由 --platform 落地，落在 --dry-run 输出第 4 节（prompt 正文与平台无关）
[8]  ★seed 记录与复现：同户型所有镜头共用一个 seed（计划文件内容哈希派生，
     --seed 可覆盖）——替代竞品 designId 保跨房一致
[9]  ★动态缺失否定词：从本房间家具清单逆向生成（平面图没有书桌 → no desk, no office chair；
     没有浴缸 → no bathtub），补模型最爱凭空补齐的件
[10] 材质 / 光影
[11] 一致性分级声明（L1 结构可保证 / L2 件数多数可保证 / L3 朝向不可靠 / L4 尺寸做不到）
[12] ★尺寸口径声明：「效果图为风格与材质意向，家具尺寸与占墙比例以平面俯视图为准」——
     **只放交付层，不进 prompt 正文**（3.0「提示词瘦身」决策：对渲染无用，只稀释硬约束权重）
```

以下工程规则在十二段式下继续有效：

- **第 [6] 段否定锁是硬约束，不是可选的"建议"**：合并顺序 = 常驻排除项 → 房间追加排除项 → 房间正向强化词
- ⭐ **排除项与正向强化词必须成对出现。** 只写"不要岩板台面"压不住 —— 模型对"看起来高级"的错配置有强惯性，必须同时写"1.5cm 厚石英石台面，底部可见衬板"
- ⚠️ **亮光 / 柔光按空间分**：卫生间柔光防滑砖（防滑优先），客厅/厨房/阳台 800×800 亮光砖。**不得全屋统一写一种。**
- 厨房地面防水属隐蔽工程、完成面不可见，**不写入排除项**，改由交付提醒输出施工要求
- 通用排除项是跨风格底板（prompt_templates.md §5-2），**每套风格都要挂，优先级高于风格排除项**
- **可施工性硬约束的有效写法**：只写"保守布局"压不住，只写"不要X"也压不住，必须**正向 + 负面两段夹击**——正面用数量词（`ONE single row of cabinets` / `ONLY TWO fixtures are present`），负面用 `CRITICAL CONSTRAINT — ...: absolutely NO ...` 逐项点名。

### 批量生成的硬性工程规范

1. **先做生成能力探测**（见 `references/workflow.md` 第零步），确认可用的图生图工具与参数名，不要凭记忆假设
2. **必须以户型图为 image1**，参考图为 image2，已确认的首张成品图作为 image3（风格锚点）。三图输入不可用时降级为单图并声明锚点未生效
3. **逐张串行调用，禁止同秒并行** —— 并行会产生同名文件互相覆盖
4. 每张图使用**独立输出目录**，生成后立即读取质检、**走 `scripts/postprocess.py` 后处理**、再重命名为规范文件名（`{房源名}_{房间}_{风格}.png`）
5. 对居中无窗房间（餐厅、玄关、卫生间），在提示词中显式写明"该房间无窗户，不得出现落地窗/侧窗"
6. 对普通平窗房间，在排除项中追加"落地窗、阳台门"
7. **⭐ 未经后处理的图片不得交付**

### ⭐ 出图后处理（每张必做）

生成 → 质检 → **后处理** → 归档。处理方法见 `references/postprocess.md`：

```bash
python scripts/postprocess.py <图...> --detect --stretch
```

| 检测结果 | 动作 |
|---|---|
| 未检出水印 | **保持原图不做处理**（不做处理是最优解，避免引入新瑕疵） |
| 底色为多结构（纹理/线稿/材质交界） | **直接裁切** `--crop`，不要试修复 |
| 底色为平滑渐变 | 逐行外推修复 `--fix` |
| 底色为平涂色块 | 中值填充 `--fix` |

处理后**必须切回正常视角目视确认**（数值达标 ≠ 视觉达标）。交付报告中记录每张图的处置方式，用于留痕。

### 多视角与跨图一致性

同一套房源所有图必须保持：同一套主辅配色、同一套墙地材质、同一套天花处理、同一套家具语言、同一套软装体系、**同一色温主光源**、同一拍摄高度（视高 1.5 米一点透视）。

## 十三、批次规模与预算上限（硬性）

| 房间总数 | 默认生成 | 处理 |
|---|---|---|
| ≤ 6 间 | 全量 P0-P3 | 直接执行 |
| 7–10 间 | P0-P1 全量 + P2 首轮 | 告知补齐预算后执行 |
| > 10 间 | **只出 P0+P1** | 必须先报预算，其余询问后补齐 |

**单批次预计消耗 > 60 积分时，必须先告知预算并等用户确认，不得静默消耗。** 质检重生成不计入预算上限（属必要成本）。

### 质检结论四档

**直接采用 / 局部修改 / 重新生成 / 不可用。**

- **空间结构错误**（门窗漂移、墙体移位、房间数量变化）→ 立即重新生成该张，不在错误结果上叠加修改
- **可施工性不通过** → 重新生成，按 `buildability.md` §5 四步兜底
- **水印未清** → **不走重生成**，走 `postprocess.py` 本地处理

## 十五、质量检查规则（4.1 改为五层归类）

每张图逐项检查 **17 项**，内容见 `references/quality_checklist.md`。**4.1 起按五层归类输出**，问题定位从"第7项不通过"变成"空间结构层不通过：门窗漂移"：

| 层 | 包含项 | 该层不通过的含义 |
|---|---|---|
| **表象层** | 配色一致性 / 材质一致性 / 文字规范 / 隐私安全 | 看得见的问题：跑色、材质乱、出乱码、泄隐私 |
| **工艺材料层** | 材质真实感 / 反射异常 / 色温一致 | 材料与光的物理问题 |
| **空间结构层** | 空间关系 / 门窗一致性 / 动线合理性 / 透视合理性 / **可施工性** | 房子本身的问题：跑户型、画不出 |
| **底层逻辑层** | 居住适配 / 收纳配置 / 跨图一致性 / 商业可用 | 这套图好不好用、能不能交给客户 |
| **方案合规层**（4.1 新增） | 避坑项：壁挂马桶 / 岩板台面 / 台上盆 / 吊轨门 / 集成灶 / 亮柔光分区 | **选的方案对不对** —— 不是画得好不好，是该不该这么配 |

批量场景规则：

- **全检不抽检**：每张都要出独立质检结论，不得合并成一句"全部通过"
- 即时重生成：质检不过的图当场重生成（上限 1 次），不带入下一张
- **后处理必做**：水印类问题走本地处理，不计入重生成次数
- 套图一致性检查：全部生成完后统一核对配色/材质/色温/拍摄高度/可施工性判定标准

### ⭐ 4.3 新增：平面图强制交付校验（批次级，与单图质检并行）

每批交付前过一遍，任一项不过 → 整批按未完成处理：

| 查 | 判定标准 | 不过的处理 |
|---|---|---|
| 平面图在场 | 交付包含 ≥1 张平面俯视图 PNG，与效果图同批 | **判定输出不完整**，补出平面图后才算交付 |
| 自检结果 | 自检报告 JSON 中 FAIL = 0；WARN 逐条进交付检查表 | FAIL > 0 → 改数据重跑；FAIL 无法消除 → 效果图与平面图整批不交付，如实报告 |
| 单位与同源 | `meta.unit` 合法且图题栏有单位行；第 7 项自检 PASS；交付报告附同源对照表（房间尺寸取自 report `room_dimensions`） | 修数据重跑或补对照表，**不得跳过** |

统一输出格式（4.1 起五层）：

```markdown

- 表象层（配色/材质/文字/隐私）：通过／不通过
- 工艺材料层（材质/反射/色温）：通过／不通过
- 空间结构层（空间/门窗/动线/透视/可施工性）：通过／不通过
- 底层逻辑层（居住适配/收纳/跨图一致/商业可用）：通过／不通过
- 方案合规层（壁挂马桶/岩板台面/台上盆/吊轨门/亮柔光分区）：通过／不通过
- 合规校验：通过／已修正 N 处
- 后处理（水印）：通过／不通过
- 主要问题：
- 建议动作：直接采用／局部修改／回退稳定底图／重新生成
```

## 二十一、异常与降级

| 情况 | 处理 |
|---|---|
| 空间图严重模糊 | 提问要求重传，不强行生成 |
| **⭐ 上传图含他人隐私或敏感内容**（4.0 新增） | **拒绝进入流程**，说明原因，不识别不总结 |
| 现场照片误当平面图 | 识别为真实空间再生成，不虚构精确尺寸 |
| 参考图风格冲突（明显两种风格） | 取主导风格直接执行并注明；用户主动问时再提供两套方案 |
| 连续生成导致户型漂移 | 停止叠加，回退稳定底图 |
| 某房间始终生成失败 | 标记缺口，交付其余房间，如实说明 |
| 达到生成上限 | 报告"已完成 N / 剩余 M"，询问是否继续 |
| **单批次预计消耗 > 60 积分** | **先播报预算并等确认**，不得静默消耗 |
| ⭐ **平面图脚本报错 / 缺 matplotlib / 中文字体缺失**（4.3 新增） | **不是跳过平面图的理由**：修复后重跑（字体缺失则降级英文标签并提示）；修不好则效果图与平面图**整批不交付**，如实报告"平面图引擎当前不可用"，严禁只交效果图 |
| ⭐ **平面图自检 FAIL 无法消除**（4.3 新增） | 效果图与平面图**整批不得交付**；如实报告 + 标注"需人工复核"，不得静默交付、不得拆开只交效果图 |
| 用户要求施工图纸/承重墙判断/报价 | 转为"空间想象示意"，不提供专业结论；**报价类要求转物料清单** |
| 用户上传敏感资料 | 不识别、不总结无关个人信息 |
| 用户要求冒充真实房源实拍 | **拒绝生成** |
| 用户只说"生成一下"且无图 | 反问要图：空间图 + 参考图（或选风格） |
| 用户不满意 | 先归类（空间结构错误/风格不对/视角不好/画像不满足/文案不合适）再针对性修改 |

### 模型能力边界（诚实降级）

**已实测：即使在提示词中明确写出净尺寸，模型仍可能画出超出净宽的布局。** 这是模型的能力边界，不是提示词写得不够。按以下顺序处理，**严禁为了凑图反复烧积分**：

| 情况 | 处理 |
|---|---|
| 提示词已给净尺寸，模型仍画不可施工布局 | 质检判不通过 → 用"严禁/绝对不要"句式强化 → 重生成；仍不行改用**该空间最保守方案**；再不行**如实告知用户该布局存在不确定性**，不硬凑 |
| 结构漂移（门窗位置变化）超过 1 次 | 停止重出，交付其余房间 + 结构可信的图，该房间标注"需人工复核" |
| 净尺寸在图纸上未标注 | **不问用户**，按最小可装尺寸取保守值推定，交付时标注"尺寸需现场复核" |
| 无图生图能力（只能文生图） | 降级为纯文字风格 + 房间清单，**明确告知用户"结构一致性无保障"** |
| 生成工具不支持多图输入 | 同上，image3 锚点失效需声明，套图色温可能漂移 |
| 后处理失败或不可修 | 如实说明"该图含平台标识，建议裁切后使用"，**不得直接交付带水印的图** |

### 图片生成不可用时的降级

明确说明"当前环境图片生成不可用，但技能定义和提示词流程已完成"，交付房间清单、风格迁移卡与全部房间的完整提示词文本。**严禁假装已经生成图片。**

## 二十二、禁止事项（红线）

不得：虚构户型中不存在的房间；复制参考图的空间形状；擅自改变承重墙、外墙和承重柱；新增或删除用户未确认的门窗；生成未经确认的精确尺寸；把示意图描述成真实测量图纸；承诺采光时长、真实面积、价格或投资收益；冒充真实房源实拍；识别或传播门牌号、姓名、电话等隐私；完整复制受版权保护的设计作品；使用暴力、违规拆改或危险施工内容；将图片输出伪装为专业建筑设计成果。

**可施工性与交付三条**：不得生成超出房间净尺寸最小可装尺寸的布局；不得未经后处理直接交付带平台水印的图片；不得在可施工性判定不通过时仍然交付而不告知用户。

**4.0 新增三条**：

- 不得**跳过上传图安全审核**直接进入生成流程；
- 不得**跳过生成前合规校验**直接调用生图；
- 不得**生成装修报价单、价格表或指定品牌型号的价格承诺**（预算档位模块未启用时）。

**4.1 新增两条**：

- 不得**交付效果图时不附《避坑提醒》** —— 只出图不提醒，等于把错误信息交给业主；
- 不得**以行业经验覆盖现行规范要求** —— 经验可加严规范，不得低于规范。⚠️ 具体条目：**厨房地面防水按 GB 50327 必须施工**，四周墙面防水层高度 ≥0.3m，不得以"无地漏""用不到"为由省略。

**4.3 新增一条**：

- 不得**只交付效果图而不交付对应平面俯视图** —— 每次调用效果图必须与平面图同批输出，缺图即本次输出不完整；脚本报错、自检 FAIL、字体缺失等技术问题一律走修复或整批不交付，**不得以任何理由拆开只交效果图**。

## 二十三、与其他技能的分工

| 技能 | 定位 | 触发时机 |
|---|---|---|
| **本技能** | 业务流程层：户型 → 全屋图 → 质检 → 物料清单 → 提案 → 文案 → 合规 | 有空间图，要整套 |
| `imagegen-hardrules` | 技术方法层：出图硬条款写法 | 任何出图需求，且提示词调不动时 |
| 装修预算/合同/监理类技能 | 报价审核、合同审计、施工验收 | 用户带报价单/合同来，或问施工验收 —— **转交，不由本技能接** |
| CAD 制图/工程量计算类技能 | 正式 CAD 施工图、工程量清单 | 用户要可编辑 CAD 或算量 —— 本技能只交付 JSON 布局数据 + PNG，说明边界后转交 |
| 通用提示词翻译类技能 | — | 🔴 **建议停用**：与本技能触发词高度重叠，且硬编码的工具依赖易失效 |

**冲突提示**："帮我生成客厅效果图"这类表述可能同时命中本技能与通用提示词类技能。执行前应确认自身加载的是本技能，避免误触发。
