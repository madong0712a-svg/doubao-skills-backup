# floorplan_2d.md — 平面俯视图（2D 线稿布局图）生成规范（v4.5）

> 本文件是《AI生成装修效果图》Skill 的**平面布置图模块**（v4.2 新增能力，**v4.3 起为强制输出项**）。
> 定位一句话：**AI 负责设计判断，程序负责精确绘图和计算。**
> 产出目标不是"看起来像户型图的图片"，而是**逻辑合理、尺寸可读、家具放得进、可直接作为后续效果图渲染布局依据**的平面方案。
> ⭐ v4.3 核心规则：**每次调用本 Skill 交付效果图时，必须同批交付至少一张平面俯视图；缺图即本次输出判定为不完整。**约束与校验机制见 §2.5。
> ⭐ v4.4 版式规则：平面图按**市面常规户型图**版式输出（深灰墙体、浅灰剪影家具、通俗图标符号、中文+拼音房名、家具尺寸压字），见 §3.3。

---

## 0. 能力边界（先读，不可协商）

| 条 | 规则 |
|---|---|
| 0.1 | 平面图**严格按用户上传户型图的原始结构**绘制：墙体、承重墙、门窗洞口的位置与尺寸零改动。家具只进场，不改房 |
| 0.2 | 输出为 **2D 正俯视、无透视、线稿风格**（白底黑线，墙体统一深灰填充、家具浅灰剪影，仅房间淡填充区分），单张高清成图；版式细节见 §3.3（v4.5） |
| 0.3 | 家具按**真实比例**摆放，比例与原始户型图一致；留足通行与开启空间，不得遮挡门洞、窗户和主要动线 |
| 0.4 | 图纸性质 = **AI 布局示意图**，默认精度等级为**方案沟通级**；完成数据核验并交付可编辑数据文件（JSON）后可声明**深化设计级**；**任何时候不得声明施工依据级** |
| 0.5 | 无可靠图纸或专业人员确认时，**不得自动判断承重墙**。墙体 role 只能按图纸图例/用户明示填写，未确认的一律按 `interior` 并在交付中提示"建议谨慎处理的结构" |
| 0.6 | 本模块不改动、不依赖效果图生成链路；平面 JSON 同时作为效果图生成的**布局依据**（layout anchor）传入 |
| 0.7 | ⭐ **4.3 强制输出**：每次调用本 Skill 输出效果图时，**必须同时输出至少一张与之对应的平面俯视图**（2D 正俯视、无透视、线稿）。缺少该图 = 本次输出不完整，不得按"已完成"交付。约束与校验见 §2.5 |
| 0.8 | 图面必须标明**统一尺寸单位**（`meta.unit`：mm 或 m，二选一，全图一致），标注数值必须与效果图空间布局同源一致（同一份 JSON 驱动），由第 7 项自检兜底 |
| 0.9 | ⭐ **4.4 版式对齐市面常规户型图**：墙体深灰填充、家具浅灰剪影 + 常规通俗符号、房间名纯中文（拼音默认关闭）、**家具/家电尺寸数值直接压在图元上或其紧邻位置（不得用引线拉到图外单独标注）**；非专业用户一眼可辨识是第一优先；避坑判定不受图标简化影响 |

## 1. 输入契约

### 1.1 必填

| 参数 | 说明 | 缺失时 |
|---|---|---|
| **户型图** | jpg / jpeg / png / pdf / dwg / dxf 任一，画面可辨认房间布局 | **不生成**，提示："未收到户型图。请上传清晰的户型图（支持 jpg/png/pdf/dwg/dxf），需能辨认房间布局与门窗位置" |
| 户型关键尺寸 | 图中标注或用户提供的开间/进深/墙厚/门窗洞宽 | 图中未标注 → 按 §5 保守推定，**全部列入待核实**，不问不猜 |

### 1.2 选填（全部有默认值）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 总面积 | `按 rooms 多边形（墙中线）累加` | 用户提供则以用户值为准（图题栏标"建筑面积（用户提供）"）并标注来源；两者冲突时并列展示，请用户确认 |
| 装修风格 | `现代简约` | 只影响家具选型与收纳配置口径，不影响墙体结构 |
| 家庭成员与功能需求 | `通用家庭，无特殊约束` | 映射为家具硬约束（见 §4.3）；不提供不追问，交付时标注 |
| 方案数量 | `1 套`（空间高效型） | ⭐ 4.3 起强制输出默认 1 套，与效果图批次一一对应；用户明确要"两套对比/高效vs舒适"时出 2 套，仍须逐套自检 |
| 输出格式 | `PNG 200dpi` | 可选 300dpi 高清；矢量/PDF/CAD 见 §7 降级规则 |

### 1.3 上传图安全审核（硬性，与主 Skill 4.0 双闸门一致）

图中含他人证件、门牌号、电话号码等隐私信息或敏感内容 → **拒绝进入流程**，说明"请裁除后重传"。不识别、不总结、不传播与出图任务无关的个人信息。

## 2. 执行流程（九步）

```
[1] 资料核验    → 识别房间/墙体/门窗/固定障碍物，标注 已确认/待核实/需现场复测
[2] 数据建模    → 按 templates/floorplan_layout_data.md 落结构化 JSON（坐标恒 mm 整数，meta.unit 定显示单位）
[3] 功能分析    → 居住画像 → 家具硬约束（必须满足/优先满足/可选）
[4] 方案生成    → ≥1 套家具布置（默认高效型；用户要对比时高效+舒适两套），各出一份 JSON
[5] 尺寸校验    → 跑 draw_floorplan.py 自检（11 项）+ 对照 §5 家具尺度表逐项核
[6] 绘制平面图  → 逐方案执行脚本，产出线稿俯视图 PNG（FAIL 清零才进下一步）
[7] 尺寸标注    → 四层标注 + 墙体厚度（§3），由 JSON dimensions 数组驱动
[8] 文字报告    → §6 报告结构（含平面图↔效果图同源对照表）
[9] 交付        → 平面图 + 尺寸标注 + 检查表 + 方案说明 + 待核实清单
                 → ⭐ 与效果图同批交付（强制配对，见 §2.5）
```

### 2.1 步骤一细则（核验）

- 图形信息 → 长度/宽度/面积数据；**图片估算值不得直接写成精确毫米尺寸**
- 尺寸闭合校验：轴线尺寸之和 = 总尺寸；不等时并列展示冲突值，请用户确认，**禁止静默取一个**
- 识别结果三级标记：已确认 / 待核实 / 需要现场复测
- 固定障碍物必须上图：烟道、燃气表、上下水、地漏、检修口、强弱电箱、梁柱降板——**禁止为了画面整洁隐藏影响布局的障碍物**

### 2.2 步骤二细则（数据模型）

JSON 必填块：`meta` / `walls` / `openings` / `rooms` / `furniture` / `dimensions`。
墙用中心线双点 + thickness；门窗挂到 wall id；房间用净边界多边形；家具用 rect+rot 或 polygon。
完整 schema 与字段说明见 `templates/floorplan_layout_data.md`，**照 schema 填，不发明字段**。

### 2.3 步骤四细则（方案生成：默认 1 套，用户要对比时 2 套）

| 方案 | 取向 | 适合 |
|---|---|---|
| **空间高效型**（默认，强制输出伴生效果图） | 收纳率/利用率优先，柜体占比高，家具取紧凑档 | 面积有限、收纳需求大、预算紧 |
| **舒适体验型**（用户要"两套对比"时才出） | 通道宽度/家具尺寸/体验优先，家具取舒适档 | 面积充足、有老人小孩、重体验 |

每套方案必须说明：家具如何摆放、动线、采光通风影响、收纳、主要通道、优点、缺点、适用家庭结构、必须满足的现场条件、是否涉及墙体拆改。
**多套方案的户型结构与墙体数据完全相同，只改 furniture 与 dimensions 家具层**——结构不随方案漂移。

### 2.4 画像 → 家具硬约束映射

| 画像信号 | 硬约束 |
|---|---|
| 有小孩（0-6岁） | 儿童房家具圆角化、不做通顶玻璃柜、地面材质偏软 |
| 老人同住 | 主通道 ≥900mm、卫生间画扶手位、不做地面高差 |
| 爱做饭 | 厨房按三角动线布柜（冰箱→水槽→灶台）；双排需净宽 ≥2400 否则单排 |
| 爱收纳 | 柜体藏八露二，提高柜体占比；禁止画无柜体样板间 |
| 常在家办公 | 书房/次卧画工作位（桌+椅+照明） |
| 频繁待客 | 客厅保证会客区完整；餐桌按待客人数取保守大尺寸 |
| 独居/两口 | 可减少次卧家具量，**不得删除户型图中存在的房间** |

画像只改家具与软装，不改户型结构。

### 2.5 ⭐ 强制输出与校验机制（v4.3 核心，每次调用必过）

**规则**：每次调用本 Skill，效果图与平面俯视图**必须同批输出**；平面图缺失 = 本次输出不完整。
以下双机制保证该规则稳定执行，**任何一环不过，整批按未完成处理**。

#### 机制一：提示词约束（生成前，把同源写死）

1. **平面 JSON 先行**：效果图提示词组装前，平面布局 JSON 必须已落盘（步骤 [2]-[6]）；
2. **布局段引用同一份数据**：效果图提示词的布局描述段（家具位置/房间关系/开间进深）
   **必须引用平面 JSON 的字段值**，不得另行描述——模板占位符见 `references/prompt_templates.md`；
3. **提示词内写明伴生交付**：效果图提示词附带声明"本图布局与同批交付的平面俯视图一致，
   尺寸以平面图标注为准"——让生成端与交付端共用同一口径；
4. **单位单一**：效果图提示词中出现的尺寸数值与平面图 `meta.unit` 同单位，不混用。

#### 机制二：输出校验（交付前，三查不过不交付）

| 查 | 内容 | 不过的处理 |
|---|---|---|
| **查一 在场** | 交付包中 ≥1 张平面俯视图 PNG（与效果图同批） | **判定本次输出不完整**，补出平面图后才算交付 |
| **查二 自检** | `draw_floorplan.py --report` 中 FAIL = 0；WARN 逐条列入交付检查表 | FAIL > 0 → 改数据重跑；FAIL 无法消除 → 平面图与效果图**整批不得交付**，如实报告"需人工复核" |
| **查三 单位与同源** | ① `meta.unit` 合法（mm/m）且图题栏有单位行；② 第 7 项自检 PASS（房间开间进深/墙体厚度标注与数据一致）；③ 交付报告附「平面图↔效果图同源对照表」——房间尺寸取自 report JSON 的 `room_dimensions`，效果图布局段引用同一 JSON | 任一不过 → 修数据重跑或补对照表；**不得跳过** |

#### 平面图无法生成时的降级（唯一例外）

仅当户型图完全无法辨认（严重模糊/倾斜/非户型内容）时，两样都不出，提示重传（§7.3）。
**脚本报错、自检 FAIL、字体缺失等一切技术问题都不是跳过平面图的理由**——技术问题走修复/如实报告，
不走"只交效果图"。

## 3. 四层尺寸标注 + 墙体厚度（draw_dimensions 数据驱动）

| 层 | JSON kind | 内容 | 规则 |
|---|---|---|---|
| 第一层 总尺寸 | `chain` | 横/纵总尺寸链（轴线/外缘） | 最外侧，加粗，分段链 + 总计 |
| 第二层 房间尺寸 | `room` | 各房间开间×进深；墙垛/柱/壁龛；阳台走廊玄关 | 房间中部，带白底衬底 |
| 第三层 门窗尺寸 | `opening` | 门洞宽、窗洞宽、洞口定位（定位距离写进文字） | 引线引出，位置紧张用引线 |
| 第四层 家具尺寸 | `furniture` + `corridor` | 家具长宽、家具-墙间距、家具-家具间距、通道最小净宽、柜门/抽屉范围、厨房操作区、洁具间距、桌椅使用范围 | **尺寸数值直接压在家具图元上或其紧邻位置，不用引线外挂**（v4.4 起，见 §3.3）；白底衬底防压线 |
| 墙体厚度 | `wall` | 所有承重墙 + 各外墙的厚度（位置由双线墙身+断口体现） | 墙中点法向引线 + "墙厚200"；内隔墙同厚可合并说明 |

标注硬规则：
- **单位统一**：全图只用 `meta.unit` 声明的单位（mm 整数 或 m），图题栏必须标明；标注文字与坐标同为该单位口径（坐标恒 mm 整数，显示层换算）；**不得 mm/m 混标**
- 尺寸数字清晰，**不得被图线穿过**
- 尺寸优先在图形外侧；位置紧张用引线（**家具层除外——家具尺寸一律压字，见 §3.3**）；**不得为画面整洁删除尺寸线**
- 不得重复尺寸、不得冲突尺寸；无法确认的标 `待核实`，**不得编造**
- 尺寸链必须闭合：分段之和 = 总计；脚本对 chain 不做自动闭合验算，**步骤五必须人工核**
- 房间 `room` 标注文字中的宽×深必须与房间净边界实际值一致；墙体 `wall` 标注数字必须与 `walls[].thickness` 一致——**第 7 项自检逐条比对**，不符即 WARN
- 家具 `furniture` 标注显式 `text` 中的「宽×深」必须与该家具图元实际宽深一致——**第 7 项自检 7c 比对**（v4.4 新增）；未写 `text` 时由脚本按图元实际宽深自动生成「名称 宽×深」

### 3.3 版式与图标规范（v4.4 新增，对齐市面常规户型图）

**目标：非专业用户一眼可辨识。** 由 `draw_floorplan.py` v4.4.0 落地，数据 schema 向后兼容（新字段全部可选，缺省行为同旧版）。

| 要素 | 规范 |
|---|---|
| 墙体 | 统一深灰填充：外墙/承重墙更深（承重墙线宽更粗），内墙浅一档；双线墙身 + 断口体现厚度 |
| 家具图标 | 浅灰填充剪影 + 常规通俗符号：床（含枕头块）、沙发（含扶手靠背）、餐桌 + 餐椅、灶台、水槽、洁具（马桶/洗手台/淋浴间）、衣柜（含挂衣杆）、书桌、电器（冰箱/洗衣机）等 |
| 门窗符号 | 门绘开启弧线，窗用四线窗；洞口定位与宽度按数据 |
| 房间名 | 中文名 + 拼音小字（rooms 可选 `pinyin` 字段；缺省不显示，行为同旧版） |
| 家具尺寸压字 | 数值直接压在图元上或紧邻位置，**不得用引线拉到图外**；自适应顺序：显式 `offset` → 一行压字 → 两行压字（名称行/尺寸行）→ 窄高图元旋转 90° → 紧贴图元下方（避让其他家具 rect 与房间名/拼音/面积文字包围盒、不越出所属房间，步进 60mm×6 次）→ 旋转 4.0pt 兜底 → 默认 offset 兜底 |
| 名称去重 | 有尺寸压字的家具块内自动名让位（块内名与压字名称行不双出） |
| 自检联动 | 渲染端与自检端共用 `furniture_label_layout` 同一落点公式——图上怎么画，自检怎么查，逐字一致 |

> 避坑判定不受图标简化影响：落地马桶、台下盆/石英石台面、推拉门形式等口径与提示词层完全一致（见 pitfall_guard.md）。

## 3.5 CAD 标注层级与尺寸线间距（v4.5，交付时必须随图说明）

| 层级 | 内容 | 间距设置 | 样式 |
|---|---|---|---|
| 第一层 细部尺寸 | 门窗洞口宽、墙段分格、房间开间进深 | 细部排外移 **1200mm** 贴图 | 45° 斜短划线 `TICK_LEN=90`（全长 180mm）、`DIM_FS=6.0pt` |
| 第二层 总体尺寸 | 各边总长 | 细部排外再移 **260mm**（`CHAIN_TOTAL_GAP`），独立成排 | 同上 |
| 第三层 引注 | 墙厚、门窗洞口定位、家具压字 | 就近 `offset` 引出 | 细实线引线 + 白底衬底 |

标注层 `zorder` 7–9，独立于墙体/家具图层。第 11 项自检禁止尺寸线相交、穿字。
图面为屏幕显示，导出固定 200dpi。

### 4.3 家具碰撞检查清单（步骤五逐项过）

- [ ] 家具尺寸 < 所在空间净尺寸
- [ ] 入户门/卧室门/卫生间门能正常开启（门扇扫掠区内无家具——**脚本自检项**）
- [ ] 推拉门不与家具碰撞
- [ ] 衣柜门/抽屉有完整开启距离
- [ ] 床两侧床尾留必要通道
- [ ] 沙发-茶几可通过
- [ ] 餐桌椅拉出不阻动线
- [ ] 厨房洗切炒关系合理（冰箱-水槽-灶台三角）
- [ ] 冰箱/灶台/水槽无冲突
- [ ] 洁具间距达标
- [ ] 定制柜不撞门、窗、开关、插座
- [ ] 家具不遮地漏、检修口、回风口
- [ ] 通行路线连续、无锐角碰撞

### 4.4 脚本自检（draw_floorplan.py 内置，交付时必须附结果）

| 检查项 | FAIL 条件 | WARN 条件 |
|---|---|---|
| 家具与墙体净距 | 嵌入墙体 >0.5mm（穿墙） | 压墙线 ≤0.5mm |
| 门洞遮挡 | — | 门扇扫掠区（门宽半径）内有家具 |
| 家具间通道净宽 | — | 最小可通行间距 <600（老人 <900） |
| 家具房间归属 | — | 家具顶点越出房间净边界 |
| 尺寸线避让 | — | 尺寸线穿过家具图元 |
| 门窗挂接 | 门窗未挂到有效墙体 | — |
| ⭐ 单位与标注一致性（4.3 新增；4.4 加 7c） | `meta.unit` 非法（非 mm/m）；家具显式标注 text 的「宽×深」与该图元实际宽深不符（7c） | 房间开间进深标注/墙体厚度标注与数据不符；图面单位混用 |
| ⭐ 标注落点归属（4.3.3 新增；4.4 随压字改制同步公式） | 家具尺寸标注（压字/offset）落点不在所属房间；房间名/面积文字压家具图块或越出本房间；房间开间标注落点越界 | 家具中心与声明房间不符；未声明 room 且几何归属不明 |

> 自检 WARN 不阻塞交付，但必须逐条写进交付报告的检查表；FAIL 必须改数据后重跑，**不得带 FAIL 交付**。

> v4.3.3 起 stdout 末行输出分步计时（prepare/render/selfcheck/total）与图元计数，报告 JSON 附 `timing` 字段——用于量化定位单次出图各环节耗时、验证优化效果。
> v4.4.0 绘图端升级为深灰墙体 + 浅灰剪影家具 + 尺寸压字 + 双语房名，单张渲染耗时与旧版基本持平（实测 300dpi 约 0.8s），版式升级不显著增加出图时间。

## 6. 交付报告结构（文字层）

```
1. 户型信息摘要（面积/层高/朝向/墙体概况/固定障碍物）
2. 需求分析（必须满足/优先满足/可选）
3. 空间面积统计表（房间/中线面积/占比；净面积需另按实测口径，不得用中线面积冒充）
4. 各空间家具清单 + 家具尺寸表
5. 方案说明（高效型；用户要对比时含舒适型）+ 平面图
6. 方案对比（仅两套时：优缺点/适用家庭/通道/收纳）
7. 尺寸与碰撞检查表（含脚本自检 8 项结果，WARN 逐条列）
8. ⭐ 平面图↔效果图同源对照表（房间/开间进深取自 report.room_dimensions，效果图布局段引用同一 JSON）
9. 收纳总量估算（投影面积，按藏八露二）
10. 动线分析（主动线/次动线/家务动线）
11. 拆改提示（可拆/不可拆/建议谨慎——不判定承重）
12. 推荐方案及理由
13. 待核实数据清单（逐条：缺什么→需谁提供→填哪里）
14. 下一步深化建议
```

### 7.3 降级规则

| 情况 | 处理 |
|---|---|
| 未收到户型图 | 不生成。提示上传要求（§1.1） |
| 户型图无法辨认房间布局（严重模糊/倾斜/非户型内容） | **两样都不出**。提示："这张图无法辨认房间布局，请重新上传清晰的户型图或平面图" |
| 图片轻微倾斜/模糊但可辨认 | 继续执行，识别项全部标"待核实" |

## 8. 脚本用法

```bash
# 单张（默认 200dpi）
python scripts/draw_floorplan.py 布局数据.json -o 平面图.png --dpi 200 --report 自检.json

# ⭐ 多张：改参数试稿 / 多方案对比 / 多份数据 —— 用批量入口（v4.5.1，实测 3.3× 提速）
python scripts/render_batch.py "a.json@200=a.png" "a.json@300=a_300.png" "b.json@200=b.png"

# 只跑自检不出图（~20ms/份，几何预检首选）
python scripts/render_batch.py --check-only a.json b.json
```

**为什么多张必须用 `render_batch.py`**：单张出图的端到端耗时里，**Python 冷启动 +
matplotlib 导入约 1.27s，而真正的绘图只有 48ms**。逐张起独立进程等于每张都付一次
冷启动税。`render_batch.py` 在**单进程内串行循环**，让冷启动只付一次
（实测 4 张：独立进程 7.9s → 单进程 2.5s，均摊 616ms/张）。

它**不复制任何绘图逻辑**——直接调用 `draw_floorplan.render_figure()` /
`build_report()` / `self_check()`，与单张出图走同一条代码路径。每轮内部会新建 fig/ax
并 `reset_text_log()`，不会出现图元跨轮残留；**也不缓存任何计算结果（含自检）**，
改了数据必须重跑，绝不会产出「数据已改、报告是旧的」这种错误。

**v4.5.2 P1：画布显式预算替代 tight**。`render_figure()` 默认不再使用
`bbox_inches='tight'`（其本质是对每个 artist 求显示路径再做贝塞尔裁剪求交，606 次/图，
实测占 savefig 耗时 ~45%）。改为：画布 = 数据范围 + `CANVAS_PAD`(300mm 文字外扩余量)、
axes 铺满 figure、像素密度 `TARGET_PX_PER_MM=0.0841`（对齐 v4.5.0 输出尺寸）。
实测热跑 render 段 551→413ms（-25%）；四边内容余量 L97/R65/T129/B48，无裁切。
`render_figure(data, out, dpi, bbox_tight=True)` 可切回旧行为对比。
**换新户型首次出图后必须目视四角**（图题栏/指北针/比例尺/总尺寸线是否完整）。

- 依赖：Python 3 + matplotlib（中文字体自适应：微软雅黑/黑体/Noto Sans CJK，找不到时告警并降级英文标签）
- 输入 JSON schema：`templates/floorplan_layout_data.md`
- dimensions 数组的 kind：`chain`（总/分段）/ `room`（房间）/ `opening`（门窗）/ `furniture`（家具）/ `corridor`（通道净宽，suffix 可改）/ `wall`（墙体厚度，4.3 新增）
- **v4.4 起**：`furniture` 标注省略 `text` 时由脚本按图元实际宽深自动生成「名称 宽×深」并压字（§3.3 自适应排版）；`offset` 降级为**可选微调字段**，不再必填；rooms 支持可选 `pinyin` 字段（中文房名下方小字读音）
- 单位：坐标恒 mm 整数；`meta.unit`（mm/m）决定图面显示单位，图题栏自动标明；第 7 项自检校验单位声明与标注数值
- report JSON 附带 `room_dimensions`（房间名 + 开间×进深），供「平面图↔效果图同源对照表」直接取数
- 退出码：0 = 无 FAIL；2 = 存在 FAIL（逐条见 stdout 与 report JSON）
- **改数据必须重跑**：任何墙体/家具/标注数据变更后，重新执行脚本出图，**不得在旧图上手改**
- `render_batch.py` 退出码与 `draw_floorplan.py` 一致：0 = 无 FAIL；2 = 存在 FAIL（不得交付）
