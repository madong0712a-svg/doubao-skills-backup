# 出图后处理

> **这一步是 3.0 新增的，也是唯一能真正消除交付事故的一步。**
> 2.0 的实测教训：5 张图全部带「AI生成 / WORKBUDDY」平台水印，生成后没做任何处理就直接交付了。

---

## 一、铁律

### 铁律 1：数值达标 ≠ 视觉达标

任何自动处理完成后，**必须切回正常视角目视确认**。
实测反例：逐行外推后残留率 0.32%、残差 std 1.13，数值全部达标，但切回正常观看时有一条**浅青色横向色带**肉眼清晰可见 —— 最终改用裁切。

### 铁律 2：水印不一定看得见

**不要凭经验"每张都裁一刀"。** 半透明白字压在纯白（255）背景上时亮度差为 0，物理上不可见、无需处理。
先按检测三件套判定，三项都干净 → 原图直接交付，不做任何处理。**不做处理才是最优解**，避免引入新瑕疵。

### 铁律 3：改提示词无效

平台水印是**后加的**，不是模型画的。提示词里写"不要水印"完全无效，必须本地处理。

## 二、检测三件套

按顺序做，任一项显示异常就做第四项读数。

```bash
python scripts/postprocess.py <图片...> --detect --stretch
```

| # | 检查 | 判据 |
|---|---|---|
| 1 | 右下角 ROI 残差 | `max` 与超阈像素数（`>6`） |
| 2 | 直方图高频值 | `std` 很低（<3）说明是纯色/平滑底 |
| 3 | 长边四角 4× 目视 | 205–255 硬拉伸后有无文字笔画 |
| 4 | **8× 对比度拉伸读数** | 自动检测全部失效时的唯一可靠手段 |

### 已知的两个失效场景

| 场景 | 症状 | 正解 |
|---|---|---|
| 水印压在大面积平滑渐变上 | 亮度差只有 3–6 个灰阶，残差法测不到 | 用 8× 对比度拉伸把水印逼出来 |
| 画面主体（大块纹理/木纹）落进 ROI | 残差顶满，像"水印从 ROI 左上角就开始" | **不要继续调阈值**，直接放大看成品 |

### 判定水印是否已清干净

**最可靠的是直接放大看成品图右下角**（4× 最近邻放大，视觉判读有无文字笔画）。
数值指标只做辅助 —— 细笔画白像素在纹理/白背景交界处天然就有上千个，**不能只看这个数字**。

## 三、水印处置决策树

| 水印底下是什么 | 方案 | 实测残留率 |
|---|---|---|
| **多种结构**（纹理 / 线稿 / 材质交界） | 🔴 **直接裁切，不要试修复** | — |
| 大面积平滑渐变 | ✅ 逐行横向线性外推 + 纵向 9px 平滑 | 0.23% |
| 大面积平涂色块 | ✅ 邻域中值 / 常量填充 | 低 |

### 已验证失败的五条路（不要重走）

`inpaint` / 二维曲面拟合 / 中值差分检测 / alpha 模板反推 / 精确笔画掩膜

其中**大框二维三次曲面拟合**残留率 37%、残差 std 15–28 —— 环带穿到主体阴影把曲面拉歪，画面出现**亮斑 + 硬边**。

### 裁切速记

```
CUT = min(水印 bbox 的 x_min, y_min) - 20，左上角对齐切方形
```

**裁切前先看主体位置**：主体偏左上、水印在右下时，裁右下对构图无损 —— 先算主体 bbox 再决定裁切线。
实测：1536×1024 的图裁到 1236×1024，水印干净消失，构图无损失。

### 渐变底修复的三个关键点

1. **取水印框左侧 70px 干净带**做逐行拟合，向右外推（不要用水印框内像素拟合）
2. **纵向 9px 均值平滑**消除横向条带（不做会留下可见色带）
3. 修完**必须目视**，不能只看残留率

## 四、乱码字修复

模型爱在道具上自发补字（书本标签、画框、吊牌、书本封面）。**即使提示词写了"简化为纯色块"，仍可能给你一串伪汉字。**

> 合规写法要双管：正面写「简化为**一块红色色块**」+ 负面写「绝不出现任何可辨识汉字」。
> 只写正面，模型的理解可能是"写成红色的字"。

处理方法：颜色检出笔画 → dilate 外扩 → `cv2.inpaint(TELEA)` → 凸包色块 + 距离高斯羽化。

```python
from postprocess import fix_garbled_text
img = fix_garbled_text(img, roi=(x0,y0,x1,y1), color_target=(80,80,200))
```

**踩坑**：直接取笔画中位色会偏砖橙/褐红（实测 BGR≈(26,62,158)，画面上看着发橙）。
做法：`target = 0.75 * 目标正红 + 0.25 * 笔画中位色`，既校正色相又保留环境色。

**该脚本幂等** —— 重复执行时色块本身会被当成笔画重新检出、重新生成，不会叠加污染。

## 五、尺寸规范化

**不要指望靠提示词要到尺寸。** 生成侧只吐固定比例，提示词里写"2048×2048""16:9"多半被无视。

正确做法：让模型按最接近目标的比例出图 → 精确尺寸走本地：

```bash
python scripts/postprocess.py <图片> --size 1536x1024
```

脚本按缩放方向自动选插值：缩小用 `INTER_AREA`（保细节），放大用 `INTER_LANCZOS4`。

## 六、标准后处理流程

```
生成完成
  ↓
① 读图质检（15+2 项，见 quality_checklist.md）
  ↓
② python scripts/postprocess.py <图...> --detect --stretch
   ├─ 未检出 → 保持原图（不做处理是最优解）
   └─ 疑似存在 → 读 8x 检视图目视确认
        ↓
③ 按底色处置
   ├─ texture 多结构 → --crop
   ├─ gradient 渐变 → --fix（走逐行外推）
   └─ flat 平涂   → --fix（走中值填充）
  ↓
④ 尺寸规范化 --size（如需要）
  ↓
⑤ ⚠️ 切回正常视角目视确认无新瑕疵
  ↓
⑥ 重命名为 {房源名}_{房间}_{风格}.png 归档
```

**❌ 禁止**：先全部生成完再统一处理。必须"生成一张 → 处理一张 → 归档一张"。

## 七、CLI 速查

```bash
python scripts/postprocess.py <图...> --detect              # 只检测
python scripts/postprocess.py <图...> --stretch             # 输出 8x 检视图

python scripts/postprocess.py <图> --size 1536x1024         # 尺寸规范化
```

## 八、Windows 环境注意事项

1. **`cv2.imread` / `cv2.imwrite` 在中文路径下静默失败**（返回 `None`，不抛异常，极易误判为"文件不存在"）。
   脚本内已统一走 `imdecode/imencode` + `fromfile/tofile`，直接调用本脚本即可。
2. **PowerShell 的 stdout 有时不回传**。落地姿势：写 Python 脚本 → 执行 → 脚本把结果写进 utf-8 文本 → Read 读回。脚本末尾有 `print("OK")` 作为存活标志。
3. Python 用隔离 venv：`%USERPROFILE%\.workbuddy\binaries\python\envs\default\Scripts\python.exe`。
