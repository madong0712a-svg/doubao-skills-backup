# 提示词模板

> 所有图片生成提示词必须按本文件的结构组装。固定模块不得删改。

---

## 一、固定提示词模块（原样包含，不得删改）

```
保持输入户型图的墙体位置、门洞位置、窗户位置、阳台位置、房间数量、空间朝向和主要动线不变；
仅迁移参考图的材质、配色、家具风格、照明氛围和软装元素；
正视摄影，垂直线条稳定，建筑透视合理；
真实室内摄影质感，柔和自然光，真实材质纹理；
家具尺度符合该房间的实际净尺寸，不使用超出净宽的对向高柜、岛台或大三人位沙发；
家具布置符合人体尺度，主通道畅通，不遮挡门洞；
地面、天花、墙面透视成立，家具稳定落地；
画面中不出现无法辨认的文字、错字、乱码和虚假广告；
画面中不出现房号、姓名、电话、门牌号等个人信息。
```

> **末行删改说明**：原第 8 行「效果图为房源空间想象示意图，不作为施工图纸」已移出提示词。
> 原因：这句话对模型渲染画面毫无帮助，只会稀释前面硬约束的注意力权重。
> **风险提示属于交付层**，写在交付报告里，不写进生成提示词。

## 三、完整组装模板

> 组装顺序：`[1] 固定模块 → [2] 户型结构 → [2.5] 布局锚点（4.3 新增，强制，见 §三之三）→ [3] 可施工性硬约束（仅 ⚠️/❌ 时插入）→ [4] 风格迁移 → [5] 该风格排除 → [6] 通用排除 → [7] 本机位 → [8] 排除项`
>
> - **第 [2.5] 段不是可选的。** 4.3 起效果图与平面俯视图强制同批交付，布局锚点段是两图同源的唯一入口，缺段即违反核心原则 19。
> - **第 [3] 段不是可选的。** 判为 ✅ 可行的房间可省略；判为 ⚠️ 或 ❌ 的房间**必须插入**，
>   否则紧凑空间会被模型画成大开间。判定标准见 `references/buildability.md`。
> - **第 [6] 段必挂。** 通用排除项是跨风格漂移的兜底，缺了会出现"简约厨房画出大理石纹"这类问题。
> - **第 [5][6] 段的顺序不能颠倒** —— 通用排除项永远在最后，优先级高于风格排除项。

> ⚠️ **排除项末尾追加（按房间类型）**：
> - 无窗房间：加「落地窗、阳台门、侧窗、任何窗户」
> - 普通平窗房间：加「落地窗、阳台门」
> - 紧凑空间（净尺寸低于最小可装尺寸）：加本空间的不可施工项，如「双排橱柜、岛台、L 型大转角」
>
> **紧凑空间排除项优先于风格关键词** —— 模型对"看起来高级"的大布局有强惯性，只在正向段写"保守布局"压不住，必须在负面段点名。

## 三之二、可施工性硬约束的有效写法（3.0 回归实测有效）

> 回归实测结论：**只写"保守布局"压不住，只写"不要X"也压不住。**
> 必须**正向 + 负面两段夹击**，模型才照做。

### 正面段：先说"只做什么"（用数量词 + ONLY/ONE）

```
ONE single row of cabinets along the back wall only.
ONLY TWO fixtures are present: a vanity and a wall-hung toilet.
```

### 负面段：用 CRITICAL CONSTRAINT + absolutely NO 反复点名

```
CRITICAL CONSTRAINT — this kitchen is too narrow for two rows of cabinets:
absolutely NO opposing tall cabinets on the opposite wall,
NO double-row galley layout, NO back-to-back stove, NO kitchen island,
NO breakfast bar, NO peninsula counter.
The walkway in front of the single cabinet row is under 900mm.
Do not widen the room, do not draw a large open kitchen.
```

**三个必备要素**：数量词（ONE / ONLY TWO）+ `CRITICAL CONSTRAINT` 标记 + `absolutely NO` 点名逐项排除。

## 三之三、布局锚点段（4.3 新增，效果图提示词强制插入）

> 用途：让效果图与同批平面俯视图**同源**。平面 JSON 先落盘并跑出自检报告后，按本段取数组装；
> **AI 不得另行描述布局**——提示词里的每个布局数值都必须能在平面 JSON / 自检报告中找到出处。

### 取值规则（三处数据源）

| 占位符 | 取值来源 | 示例 |
|---|---|---|
| `{房间名 开间×进深}` | 自检报告 JSON 的 `room_dimensions`（按报告里的单位原样取） | `客厅 6900×4800` |
| `{家具清单 + 贴墙/定位关系}` | 平面 JSON `furniture` 数组（type/name/rect + attach_to） | `三人沙发贴西墙（距南墙 1500）` |
| `{门窗洞口位置}` | 平面 JSON `openings` 数组（wall + center + width） | `阳台推拉门 2400 宽，居中南侧` |
| `{尺寸单位}` | 平面 JSON `meta.unit`（mm 或 m，全提示词统一，禁止混用） | `mm` |

### 硬规则

1. **先平面后效果**：布局锚点段取值前，平面图必须已出且十一项自检 FAIL=0；平面图没出来，效果图不出（核心原则 19）；
2. **改布局 = 改 JSON 重跑**：任何家具/尺寸调整必须改平面 JSON → 重跑 `draw_floorplan.py` → 再更新效果图提示词；**不得只改提示词不改 JSON**（两图漂移即同源失败）；
3. **单位单一**：提示词中所有尺寸数值与 `meta.unit` 一致；`mm` 时写整数毫米，`m` 时写米（如 6.9×4.8）；
4. **同源对照**：交付报告中的「平面图↔效果图同源对照表」房间尺寸行直接取自 `room_dimensions`，与提示词布局段逐格核对；
5. **v4.4 版式说明**：平面图家具/家电尺寸以压字形式直接标在图元上或紧邻位置（无引线外挂）；效果图布局段引用的家具尺寸数值须与平面压字一致，但**不要求在效果图中复现标注样式**（效果图不画尺寸标注）。

## 五、风格关键词参考库

> **每套风格都由「正向关键词」+「【必须排除】」两部分组成，缺一不可。**
> 原因：模型对每种风格都有很强的默认惯性，只写"要什么"会得到混淆体
> （例如写"简约"得到北欧白盒子、写"原木"得到日式性冷淡）。
> **近似风格必须用负面项逐个点名排除**，见每套末尾的【必须排除】块。
>
> ⚠️ **使用时务必在每套的【必须排除】之后，再追加「§5-2 通用排除项」**——
> 排除只挂在本风格内是不够的，模型会把别处风格描述里的词（岩板、大理石）
> 借用过来。通用排除项是跨风格漂移的兜底，**每套都要挂**。

## 五之二、通用排除项（3.0.1 新增，每套风格都要挂）

> **为什么需要独立一节**：3.0 回归实测发现两个跨风格漂移问题 ——
> ① 现代简约的厨房墙被画成了**大理石纹**（风格库写的是"哑光瓷砖"）；
> ② 简约主卧出现了**明显踢脚线**（风格库写"哑光、克制"但没禁）。
>
> 根因：**排除项只在本风格内生效**。模型会把别处风格描述里的词（岩板、大理石）
> 借用到当前房间。所以排除不能只挂在风格上，**必须有一条跨风格的通用底板**。

在每套风格的【必须排除】之后、排除项末尾统一追加：

```
【通用排除项 —— 任何风格都不应出现】
不要大理石纹、岩板纹、木纹壁纸出现在非指定墙面（背景墙以外一律不要）；
不要厚重踢脚线、欧式装饰线框、描金石膏线、罗马柱、拱券造型；
不要外挂全屋中央吊灯（层高已确认 ≥2.9m 且无中央空调时才做无主灯；层高未标注或 ≤2.9m 一律用主灯）；
不要格栅木饰面满墙铺（仅新中式局部使用）；
不要黑色金属外露管线、工业风裸墙、铁艺爬梯；
不要纯白无任何材质的墙面（哑光乳胶漆也要有细微质感）；
不要金色镜框、水晶灯、丝绒壁纸。
```

> **适用顺序**：通用排除项永远是最后一道，优先级高于风格排除项。
> 组装顺序：`固定模块 → 户型结构 → [可施工性] → 风格迁移（正向 + 该风格排除）→ 通用排除 → 本机位 → 排除项`

### 通用排除项与色温修正的验证结果（3.0 回归实测）

| 问题 | 修正前 | 修正后判定 |
|---|---|---|
| 现代简约厨房墙出现大理石纹 | ❌ 未禁 | ✅ 通用排除项第 1 条拦截 |
| 简约主卧出现厚重踢脚线 | ❌ 未禁 | ✅ 通用排除项第 2 条拦截 |

## 五之三、照明色温判据

> 色温不是随手填的，必须与风格和空间功能匹配。**色温错了，风格就错了。**

| 色温 | 适用 | 说明 |
|---|---|---|
| **3000K 暖白** | 无主灯住宅空间、奶油原木、新中式、轻奢、木质感空间 | 住宅标准暖白，最显温馨 |
| **3500K 中性偏暖** | 现代简约、北欧 | 需略暖才不显办公感 |
| **4000K+ 中性/冷白** | **仅限厨房、卫生间、玄关等功能性空间** | 全屋使用会显冷、显办公 |

**套图一致性要求**：同一套图的主光源色温必须统一，**只允许功能空间偏离**。
跨图色温漂移是批量出图的高发错误，质检第 11、12 项要逐张核。

## 七、图片生成调用参数规范（2.0 批量直出）

### 三图输入（全屋一致性的关键）

| 参数 | 内容 | 作用 |
|---|---|---|
| `image1` | **户型图** | 结构基准；缺它模型会虚构门窗 |
| `image2` | 效果参考图 | 风格来源 |
| `image3` | 已确认的首张成品图（通常为客厅） | 风格锚点，锁定跨图材质与色温 |

纯文字风格描述时不用 image2/image3，风格关键词必须写全。

### 批量生成硬性规范（实战教训固化，必须遵守）

1. **逐张串行调用，禁止同秒并行**——并行会产生同名文件互相覆盖
2. 每张图使用**独立输出目录**（如 `outputs/{房间名}/`），生成后立即读图质检
3. 质检通过后重命名为 `{房源名}_{房间}_{风格}.png` 统一归档
4. 质检不过当场重生成（上限 1 次），仍不过标记缺口继续下一张
5. **无窗房间**（餐厅/玄关/卫生间等居中空间）必须在提示词写明：
   ```
   重要：该房间位于户型内部，没有任何窗户，画面中不得出现落地窗、阳台门或侧窗；
   自然光只来自远处相邻房间的窗户和室内的漫射照明。
   ```
6. **普通平窗房间**必须在排除项追加：`落地窗、阳台门`

### 通用参数建议

| 场景 | 参数 |
|---|---|
| 出图比例 | 横图 `1536x1024`；社交竖图 `1024x1536`；方图 `1024x1024` |
| 画质 | `high` |
| 多视角一致性 | 后续所有房间复用同一段【风格迁移】文本 + image3 锚点 |

### 各房间机位速配（批量默认）

| 房间 | 默认机位 |
|---|---|
| 客厅 | ① 入口内侧正视主墙/电视墙 ② 望向阳台/采光面（P0 出 2 张） |
| 主卧 | 门口向床背景墙与飘窗正视 |
| 餐厅 | 客餐交界处向厨房方向正视（无窗房间写无窗约束） |
| 次卧 | 门口向床与窗正视（平窗房间排除落地窗） |
| 书房 | 门口向书桌与飘窗正视 |
| 厨房 | 门口向内正视，展示 U 型/L 型橱柜与北窗 |
| 卫生间 | 门口向内正视，干湿分区、镜柜、明亮整洁 |

## 八、禁止写入提示词的内容

- 精确尺寸标注（"客厅宽 4.2 米"）
- 施工承诺（"可拆除""加装承重"）
- 隐私信息（房号、姓名、电话、门牌号）
- 虚假实拍表述（"真实实拍图""现场拍摄"）
- 采光时长承诺（"每天日照 6 小时"）
- 投资收益承诺（"升值""保值"）
