# render_consistency.md — 平面图↔效果图 严格一致协议（v4.6.0）

> 本文件是 v4.6.0 的核心新增。它记录一次真实事故的复盘、根因、修复方案，
> 以及**当前技术条件下能做到什么、做不到什么**。出效果图前必读。

---

## 一、事故复盘（2026-10-19，91.5×114 两室两厅极简方案）

### 现象
用户连提两轮，指出效果图与平面图不一致：

| 轮次 | 用户指出 |
|---|---|
| 第 1 轮 | 主卧效果图有办公桌、平面图没有；次卧床朝向不一致；次卧效果图 2 个床头柜、平面图 1 个；卫生间马桶朝向不一致 |
| 第 2 轮 | 次卧效果图衣柜与推拉门"相对"，平面图"同侧"；衣柜尺寸效果图与平面图明显不一致 |

### 根因（四层，逐层剥离）

**根因 1：平面图本身画错了（最严重）**
回查原图发现三处硬错，效果图只是在"如实反映错误的平面图"：

| 项 | 平面图（错） | 原图实际 |
|---|---|---|
| 次卧门 | 在**西墙** y5050 | 门弧在**北墙西端**，弧心 x≈5900、门宽 840 |
| 次卧衣柜 | 误放南段起点 y3650、长 900 | 贴西墙，长≈1240 |
| 次卧床 | 离南墙 50 | **贴南墙**（净深 2050 的唯一解法） |

> **教训**：用户报"不一致"时，**先怀疑平面图**，不要直接改效果图。
> 低分辨率原图（本次 500×660px，1px≈31mm）的家具位置必须逐件回查，
> 不能凭"看起来在那"落坐标。

**根因 2：人工转写环节必然漂移**
平面图里是"rect 坐标 + 家具类型"，提示词里要变成"床头靠哪面墙、朝哪开"。
这个转写由 AI 手工完成 → 漏写、写反、凭印象补对称，全是必然。
本次主卧"多出书桌"就是模型按"卧室应该有书桌"自行补的。

**根因 3：提示词只描述"有什么"，没锁"朝哪、几件"**
首版提示词写"床靠东墙"，模型理解为"床头朝东墙那一侧"或"床贴着东墙摆"，
两种都合理，于是画成南北向。缺的是：
- 朝向锁（headboard against the EAST wall / foot pointing toward camera）
- 数量锁（exactly ONE nightstand，**并显式否定第二个**）
- 否定锁（NO desk, NO chair —— 不写就会被补）

**根因 4：模型对"局部长度/比例"服从度极低（能力边界）**
"衣柜只占西墙南段 58%"这一条，用四种表述各试一次，全部失败：

| 表述 | 结果 |
|---|---|
| `the southern half of the west wall` | 画成整墙柜 |
| `exactly 58 percent / four door leaves max` | 画成整墙柜 |
| `two equal halves, nearer half bare` | 房间变形为走廊，朝向也乱 |
| `half nearest camera is empty wall` | **柜子直接消失** |
| 最终（脚本生成，含 59% + 与门相对关系） | 柜子跑到近端（方向反）、床变南北向、推拉门画成平开门 |

> **结论：扩散模型能可靠执行"有什么 / 在哪个墙 / 朝哪个方向"这类定性约束，
> 不能可靠执行"占这面墙的百分之多少"这类定量约束。**

## 二、修复方案（已落地）

### 修复 1：新增必填字段，杜绝"靠猜"
`furniture` 增加两个**可选但关键家具必填**的字段：

| 字段 | 取值 | 用途 | 必填范围 |
|---|---|---|---|
| `head` | `"N"` / `"S"` / `"E"` / `"W"` | 床头靠哪面墙、马桶水箱贴哪面墙 | `bed`、`toilet` **必填** |
| `against` | `"N"/"S"/"E"/"W"` 或数组 | 贴哪面墙；L 形房间的 bbox 判定会失准，必须显式给 | 见 `ADHERE_REQUIRED` |

**没有 `head` 的床 = 出图必然画反**。这是本次事故最直接的修复。

### 修复 2：提示词改由程序生成，禁止人工转写
新增 `scripts/make_room_prompts.py`：

```bash
# ① 出图前一致性预检（缺字段直接拦下，退出码 2）
python scripts/make_room_prompts.py plan.json --check

# ② 生成全屋逐房间布局卡（含提示词）
python scripts/make_room_prompts.py plan.json -o 布局卡.md

# ③ 只取某间的提示词，逐字复制去生图
python scripts/make_room_prompts.py plan.json --prompt R06
```

它做的事：
- 房间 polygon 四边 → N/E/S/W，与 `walls` 按坐标匹配，自动得出"哪面墙有门窗"
- 家具 rect 距墙内表面 ≤120mm → 自动判定贴墙（可用 `against` 覆盖）
- 按 `head` 归墙：床/马桶归到**床头/水箱所靠墙**，不是归到侧靠墙
- 自动生成**数量锁**与**否定锁**：只有 1 只床头柜 → 自动写
  `exactly ONE nightstand ONLY` + `FORBIDDEN: no second nightstand`
- 只占部分墙面时，追加"相对关系"提示（`covers about 59 percent … the doorway side must be empty`）
- 同一道墙服务多个房间时，按洞口中心投影范围过滤，避免门窗串号

**规则：效果图提示词必须逐字取自脚本输出，不得人工改写、不得凭记忆补段。**

### 修复 3：出图顺序改为「平面图先行 + 逐房间确认」
见下节。

## 三、调整后的出图流程（v4.6.0 强制）

```
[1] 读图 → 落布局 JSON（墙/门窗/房间/家具，含 head 与 against）
        ↓
[2] python scripts/make_room_prompts.py plan.json --check
        ↓ 有告警 → 回改 JSON，不得带告警出图
[3] ★ 出平面俯视图（draw_floorplan.py / render_batch.py），自检 FAIL=0
        ↓
[4] ★★ 平面图交用户确认 —— 这一步没确认，后面一步都不许做
        ↓ 用户挑错 → 回 [1] 改 JSON → 重出平面图 → 再确认
[5] 按优先级逐房间出效果图（一次一间，不批量闷头出）
        ↓ 提示词：make_room_prompts.py --prompt RX 逐字复制
[6] 每张出完立即做「三查」，见下表
        ↓ 不一致 → 修提示词重试，同一间最多 2 次
[7] 2 次仍不一致 → 停止重试，如实标注该图「布局为示意」并说明差在哪
        ↓
[8] 全屋拼齐 → 交付报告附「平面图↔效果图 逐项核对表」
```

### 为什么必须"平面图先行、确认后再出效果图"
本次事故的直接代价：平面图错了 → 5 张效果图全部白出 → 改了平面图 → 又要重出。
**平面图是 2 秒能改的矢量图，效果图是每张要付费生成的位图。**
先用最便宜的产物把布局定死，再花贵的预算。

### 每张效果图出完的「三查」
| 查项 | 怎么查 | 不合格怎么处理 |
|---|---|---|
| **结构查** | 房间数、门窗位置与类型、朝向是否与平面图一致 | 结构错 → 重试；2 次不过 → 停止，标注 |
| **清单查** | 家具**件数**与**种类**是否与平面图一致（尤其"有没有多出来"） | 多出/少了 → 重试；床与柜的朝向优先 |
| **朝向查** | 床的床头、马桶水箱、衣柜所在墙、门/窗所在墙是否对 | 朝向错 → 重试 |

> 三查必须**逐项对着平面图看**，不能凭"看起来差不多"。

## 四、能力边界（必须写进交付报告，不得含糊）

| 等级 | 一致性内容 | 当前能否保证 | 说明 |
|---|---|---|---|
| **L1** | 房间数量、相对位置、门窗所在墙与类型 | ✅ 基本可保证 | 结构层，模型对"哪面墙有窗/门"服从度较高 |
| **L2** | 家具有哪些、各几件 | ⚠️ 多数可保证 | 靠 `COUNT LOCK` + `FORBIDDEN` 压制；仍偶发多出小件 |
| **L3** | 家具朝向、贴哪面墙 | ⚠️ 不可靠 | **本次事故主战场**；靠 `head`/`against` + 逐字提示词显著改善，但窄房/异形房仍会错 |
| **L4** | 家具/柜体的**具体长度、占墙比例** | ❌ **做不到** | 模型对百分比类约束服从度极低，实测 5 种表述全败 |

### 因此，交付话术必须这样写
> 效果图为**风格与材质意向图**，空间结构（房间/门窗/朝向）已按平面图核对；
> **家具的具体尺寸与占墙比例以平面俯视图为准**，效果图中柜体长度等可能与图纸存在差异。

**禁止**在交付中声称"效果图与平面图完全一致"——L4 做不到，这是虚假陈述。

### 若客户要求 L4 级严格一致
文生图做不到，应改用**建模渲染**路线：
SketchUp + Enscape / 酷家乐 / 三维家 —— 从同一份布局 JSON 建体量，
尺寸天然与平面图一致。本 skill 的价值定位是"低成本快速风格意向"，
不是"精确施工级表现"。

## 五、给后续维护者的检查清单

- [ ] 平面图自检是否 FAIL=0 且**已交用户确认**？
- [ ] `--check` 是否 **0 告警**？床/马桶是否都有 `head`？
- [ ] 每个房间的提示词是否**逐字来自脚本输出**（而不是手写）？
- [ ] 每张效果图是否过了**三查**？
- [ ] 交付报告是否附了**逐项核对表**，并如实标注 L4 差异？
- [ ] 是否**没有**声称"完全一致"？
