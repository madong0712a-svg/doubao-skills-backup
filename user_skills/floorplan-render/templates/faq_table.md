# 常见追问处理表（对话层口径）

> **用途**：用户开口追问之后，按本表接话。凡命中左栏（含同义句），按中栏口径执行，
> 不得自行发挥、不得新增承诺。
>
> **与其它章节的分工**：
> - SKILL.md 第十九节《修改指令分类》管「改什么」；本表管「说什么」。
> - 收费、重出、免费口径一律以 `templates/billing_contract.md`（计费契约表）为唯一口径；
>  两表冲突时**以计费契约表为准**，并回头修正本表。
> - 口头禅红线：任何回答不得出现「绝对可行」「保证能装」「百分百没问题」「完全一致」。
>
> **版本**：4.6.1 新增（对标竞品 plan-to-render 追问表，按本技能两道闸 / 平面图先行 / L1–L4 一致性分级改造）

## 一、效果与预览类

| 用户说（含同义句） | 处理口径 | 依据 |
|---|---|---|
| 「先看看效果」「能先出一张看看吗」 | **我们的预览门是平面图，不是效果图**：先出平面俯视图（约 2 秒、零出图成本），布局确认后才出效果图。平面图就是「效果」的可改版预览——现在改不花钱，出了效果图再改每张都要付费。用户坚持要先看一张渲染效果：说明单张成本后按预览门出主空间 1 张，计入本次总额，不额外收费 | 4.6.0 铁律一 |
| 「为什么先出平面图，直接出效果图不行吗」 | 用一次真实事故说明：平面图有错（次卧门位/衣柜/床位）导致 5 张效果图全部白出再重出。平面图是 2 秒可改的矢量图，效果图是每张付费生成的位图——**先用便宜的校验贵的** | 4.6.0 铁律一 |
| 「平面图能改吗」「床挪一下」「门换个方向」 | **能，且未出效果图前的修改不另计**：改布局 JSON → 重跑十一项自检（FAIL=0）→ 出新平面图交用户确认 → 确认后才动效果图 | 计费契约表·平面图阶段修改 |
| 「效果图跟平面图不一样怎么办」 | 先分级再处理：**结构/门窗/朝向不一致（L1）→ 属质量事故，重出不另计**；家具件数（L2）/朝向（L3）偏差 → 可重出该房间；**尺寸与占墙比例（L4）→ 文生图做不到**（模型对百分比类约束服从度极低，5 种表述实测全败），以平面俯视图为准，严禁声称完全一致；客户坚持要 L4 级一致 → 转建模渲染（SketchUp+Enscape / 酷家乐），文生图做不了 | render_consistency.md |
| 「风格能不能照抄参考图的房子」 | **只搬风格，不搬房子**：参考图仅迁移配色/材质/家具/照明等 12 项可迁移属性；墙体、门窗、房间数量、朝向一律按上传的户型图，不可复制参考图户型 | 核心原则 1/2 |

## 二、尺寸与用途边界类

| 用户说（含同义句） | 处理口径 | 依据 |
|---|---|---|
| 「尺寸对不对」「是按我的尺寸来的吗」 | 净尺寸已写入提示词与平面图；但**效果图的家具尺寸与占墙比例不作精确还原（L4 能力边界）**，尺寸一律以平面俯视图为准，建议现场复尺。不得回答「完全按你的尺寸」 | render_consistency.md |
| 「能当施工图用吗」「照着这个装行不行」 | **不能**。效果图与平面图均为 AI 生成的空间想象示意，不构成施工依据；承重墙判断、拆改可行性、管线走向须以现场勘测与专业设计图纸为准。顺势转物料清单（示意口径，非实测工程量） | 风险提示节 |
| 「能出水电定位图 / 报价单吗」 | 不在职责内：报价类要求**转物料清单**（明确标注非实测工程量、不含价格）；水电定位图建议找专业方，不提供专业结论 | 第一节·用途边界 |
| 「这是我家真实照片吗」「能冒充实拍发出去」 | **拒绝生成/拒绝冒充**。每张效果图必带「AI 生成示意图」风险提示；房源展示场景须向看房方明示 | 异常与降级节 |
| 「图上有水印 / 乱码字」 | 属交付事故：出图后处理后（清平台水印、修乱码字）才归档，**带水印的图不交付**；用户发现漏网图 → 重新处理后补交付，不计入免费微调次数 | 核心原则 11 |

## 三、修改与重出类

| 用户说（含同义句） | 处理口径 | 依据 |
|---|---|---|
| 「这张不满意」「重画」 | **先归类再动手**（空间结构错误 / 风格不对 / 视角不好 / 画像不满足 / 文案不合适），按第十九节分类处理。因我方质量原因（结构错误、朝向画反、水印、自检 FAIL）重出**不另计**；纯偏好性重出（无质量问题的换风格/换机位）先说明成本再出 | 第十九节 + 计费契约表 |
| 「换个风格再看看」「奶油原木也来一套」 | 复用户型解析与房间清单，换风格迁移卡，批量重出（走对比交付，每张独立质检，不因对比降低标准）。属新一批次：**先播报预算再出**，不先斩后奏 | 对比交付节 |
| 「多加一间房」「把书房也出了」 | 按 P0–P3 优先级补生成；单批 >10 间房只出核心空间，其余列清单问后再补 | 预算控制 |
| 「所有房间灯都换成暖光」 | 批量修改：逐张按同一指令串行重生成，跨图一致性规则不变；一次只处理一个主要修改目标 | 核心原则 4 |
| 「怎么自己改提示词」 | **提示词由脚本生成、逐字复制使用，禁止人工转写**（人工转写「rect 坐标 → 朝哪面墙」必然漏写、写反、凭印象补对称——已出过主卧凭空多书桌、次卧床画反、床头柜多一只三起事故）。想微调把需求说成人话，由脚本重出 | 4.6.0 铁律二 |
| 「有老人 / 小孩 / 宠物，图上注意一下」 | 好——更新居住画像卡，按画像硬约束重出受影响房间（儿童房圆角家具、老人房预留扶手位、紧凑空间收纳优先）。**画像只改家具与软装，不改户型结构**，不得以画像为由增删房间、移动墙体门窗 | 第八节 |
| 「多久能好」「快点」 | 平面俯视图约 2 秒；效果图逐张付费生成、串行质检 + 后处理，全屋一批通常数分钟内。卡住时如实报告「已完成 N / 剩余 M」，不静默 | 异常与降级节 |

## 四、收费与隐私类

| 用户说（含同义句） | 处理口径 | 依据 |
|---|---|---|
| 「为什么要收费」「能免费吗」「便宜点」 | 按计费契约表口径：安装免费、按次计费；免费档模型（FLUX.1-schnell）出图不计费；同风格内微调免费 1 次。**不主动承诺降价、不私下改口径**，改价先改计费契约表 | 计费契约表 |
| 「我上传的户型图里有家人照片 / 身份证」 | 上传图先过**第一道安全闸**：含他人隐私或敏感内容 → 拒绝进入流程，不识别、不总结，说明原因并请其裁去后重传 | 核心原则 12 |
| 「别人的图能帮我出吗」 | 只能处理用户有权使用的图；无法确认权属且含他人隐私 → 婉拒 | 用途边界 |
| 「批次怎么这么贵」 | 出示计费契约表单次包含项（解析 + 平面图 + 客厅 2 张 + P0–P3 各 1 张 + 全套报告文案）；超 60 积分的批次本应提前播报——未播报是我方失误，按契约表退款规则处理 | 计费契约表 |

## 使用示例（内部）

用户：「先给我看一眼效果呗」
→ 命中第一类第 1 行：答「先出平面俯视图给您确认布局（约 2 秒，不产出图费用），
平面确认后立刻逐间出效果图；平面阶段改布局不花钱，效果图出来后每张都是付费生成的」。
**不得**直接跳过热门出 1 张效果图——除非用户明确坚持，且已被告知单张成本。
