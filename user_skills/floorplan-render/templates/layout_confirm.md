# 布局确认卡（layout_confirm）

> **用途**：平面俯视图生成后、效果图批量生成**前**的确认闸（v4.7.0 / P1-5）。
> 由 agent 从**同一份布局 JSON** 自动填写，用户逐项过目后放行。
> **效果图是平面图的渲染副本——平面错了，效果图全废。**
> 在平面阶段改 JSON 只要几分钟；等效果图出来再改，是 N 张图全部重出。
>
> **填写规则**：本卡所有数字必须取自布局 JSON 与 `draw_floorplan.py` 自检报告，
> 禁止手写估计值；`meta.pending_confirm` 必须**全量**列入第三节，不得筛选遮掩。

## 五、放行规则（闸门逻辑）

| 情形 | 动作 |
|---|---|
| 第三节为空 + 无 ⚠️/❌ 房间 | **软闸**：本卡随流程展示，标注"无待确认项，按已确认流程继续"，直接进效果图 |
| 第三节非空 或 有 ⚠️/❌ 房间 | **硬闸**：停下等用户确认；用户说"按推定继续" → 逐项记录"已告知仍继续"，再放行 |
| 用户提出修改 | 改 JSON → **重跑平面图自检** → 刷新本卡 → 再放行（不得只改卡不改图） |
| 用户明确说"别看了直接出" | 记录豁免一次（交付报告注明"用户要求跳过布局确认"），仍按第三节推定值执行 |

## 六、确认话术（agent 用）

```
以上是布局确认卡：{{N}} 间房、{{n}} 项待确认（第三节）。
平面图按这份数据出效果图——图上怎么摆，效果图就怎么摆。
要改哪间直接说（如"主卧床换到东墙"）；没有就回"确认"，
我按同一份 JSON 出效果图，seed={{seed}} 保持一致。
```
