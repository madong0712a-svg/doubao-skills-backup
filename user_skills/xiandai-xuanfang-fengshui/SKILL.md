# 现代选房风水：由外而内三层研判

一套 20 年房产实操沉淀的现代选房风水方法论。核心立场经过明确校准，执行时不得偏移。

## 一、立场与边界（先读，不可跳过）

**第一，风水学不是鬼神之说。** 堪舆不是求神问卜的迷信。风水的本质是古人用经验总结出的"宜居环境说明书"，背后是环境学、地理学、心理学的结合，目的是让居住更安稳舒心。解释现象时优先给出可验证的现代理由（季风、温度调节、狭管效应、噪音灰尘、心理压迫感），传统术语保留但必须翻译。

**第二，现代住宅不宜以古代标准过度苛求。** 现代住宅与古代建筑在外形、功能、居住理念上存在显著差异，观点应与时俱进、灵活调整。判定纪律：**较真但不过度**——先核实强度（距离、高度、遮挡、朝向），再下结论；轻微问题明确告知"不会有太大影响"。

**第三，选房如选对象。** 房子要好好选，一旦出现问题，换房不是一件轻松容易的事情。所以本技能的价值在于**事前排查**，不是事后安慰。

**合规红线**：不以风水之名行迷信之实；不做运势、财运、健康的确定性承诺（用"影响居住体验/心理感受/流通性"表述）；涉及二手房历史用途（凶宅、不洁用途）等敏感信息的核查，只给核查方法与判断原则，不替用户定性；所有结论附"仅供参考，重大决策请结合实地看房与专业意见"。

## 二、判定顺序：由外而内（择局为先，择层为后）

**顺序不可颠倒**：先研判小区外部环境与气场 → 再到楼栋建筑周边 → 最后才是住宅内部精细化考量。

理由：外部环境无法改变（换房成本极高），内部布局多数可通过装修化解。把 80% 的注意力放在外部，是本方法论与普通看风水最大的区别。

## 三、工作流程

### Step 1 收集信息

- 小区位置与周边环境（有无水系、道路走向、周边建筑与设施）
- 楼栋在小区中的位置、前后左右楼栋关系与层数
- 户型图（用于判定方正度、缺角、厨卫位置、门的关系）
- 已知的顾虑点（用户自己感觉不对的地方）

信息不全时按已知项先研判，缺项标注"需实地核实"，并给出核实清单。

### Step 2 室外研判

加载 `references/outdoor-fengshui.md`，逐项核查：
1. **四象布局**：后有靠山、右低于左、前方开阔明亮（高层城市按"后排有楼栋、右楼低于左楼、前方无遮挡"判定）
2. **水局**：明堂见水 / 水聚天心 / 玉带环腰三选一，必须活水清澈；高架高速不算水
3. **藏风**：要柔和轻风，忌风口与强风直吹
4. **煞气**：尖角、天斩、反弓、路冲、顶心逐项核实强度并给化解方案
5. **外部不利因素**：建筑类 / 场地类 / 工厂类 / 环境类四张清单逐项排查

### Step 3 楼栋研判
楼栋是否处于小区中心或有楼栋作靠山、右低左高关系、归家动线是否安静有序。

### Step 4 宅内研判
加载 `references/indoor-fengshui.md` 与 `references/huxing-fengshui.md`：
1. **阳宅三要**：厨房（方位/刀具/冰箱/炉灶/厨卫关系）、大门玄关（不直冲、透而适中、采光）、卧室（床不靠窗、不对镜、不在横梁下、衣柜在床左）
2. **缺角**：对角线法测量，超半径 1/2 为缺角，超 2/3 为严重缺角，对应方位对应家人
3. **户型形态**：中心卫生间、三角形、T 型、多边形、刀把形等缺陷户型

### Step 5 量化评分与结论

用脚本输出标准化评分卡：

```bash
# 生成空白评分模板
python3 scripts/fengshui_score.py --template > pingfen.json
# 填写各评分项后计算（室外45 + 楼栋15 + 宅内40 = 100分）
python3 scripts/fengshui_score.py --input pingfen.json
```

等级：**A 优选 ≥85 / B 合格 70-84 / C 需化解 55-69 / D 不建议 <55**。

**一票否决**：存在下列情况时无论总分高低均判 D——历史不洁用途、曾发生非正常事件、曾用于忌讳行业、危险地势、宅基有问题、地下采光不良空间住人、易淹低洼地势、建筑体过于奇特。此类情况无有效化解之法，直说"建议不要住"。

### Step 6 输出结论

固定结构：基本信息 → 三层逐项核查（每项：判定 + 依据 + 影响 + 化解）→ 评分卡与等级 → 一票否决检查 → 行动建议（换房 / 化解 / 可接受）→ 免责声明。

### Step 7 内容分发（可选，用户说"做选题/出稿"时执行）

加载 `references/content-topics.md`，把研判能力转成可分发内容：

- **选题生成**：按「基础层 40% / 进阶层 40% / 决策层 20%」金字塔配比，从七大主题（方法论/水局/煞气/外部清单/阳宅三要/缺角户型/硬伤房源）中产出选题清单，每条给标题（按六种标题公式）+ 核心观点 + 内容形式
- **公众号**：1500-2500 字长文，方法论 + 案例 + 清单，结尾带自查表与互动提问
- **短视频**：60 秒竖版口播，固定五段式（3 秒钩子 → 反常识 → 判定标准 → 化解/结论 → CTA），可编成「看房风水十讲」系列
- **小红书**：图文分点 + 判定标准图解，标题用"建议收藏"体
- **联动**：长文拆短视频 → 评论区收真实户型图 → 下期用真实案例回应（形成选题闭环）

**纪律**：一律脱敏（隐去楼盘名、门牌、业主信息）；标题禁确定性承诺；结尾带免责声明。

### Step 8 推公众号草稿箱（用户说"存到公众号后台/推草稿/发公众号"时执行）

测评成稿后走既有推送链路直推，不要再问版式：

1. **版式**：用「墨色下划线」微信安全版式（全内联样式、无 SVG、无外部 CSS）。骨架：外层 section（15px/#3f3f3f/行高1.9）→ 灰底引言块（border-left 3px #2b2b2b + #f7f7f7）→ 总分 strong 22px #2b2b2b → h2 17px 加 border-bottom 2px #2b2b2b → 结尾署名免责脚（灰底 + border-top 2px）。正文图表一律内联样式，避免用复杂 table。
2. **配图**：四象方位图用 SVG 写好（viewBox 0 0 680 H，全内联 fill，白底 rect），再用 sharp 渲染 750px PNG：
   `NODE_PATH="$(npm root -g)" node -e "require('sharp')('x.svg',{density:200}).resize({width:750}).flatten({background:'#fff'}).png().toFile('x-750.png')"`
   （sharp 装在全局时用上面的 `npm root -g`；装在项目本地就直接 `node -e ...`，不需要 NODE_PATH。）
   HTML 里留 `{{XXX_IMAGE}}` 占位符，上传后自动替换。
3. **推送**：本技能不内置推送脚本，用你环境里已有的草稿箱推送工具（如 `push-draft.cjs`），按下述参数调用：
   ```
   node <推送脚本目录>/push-draft.cjs \
     --html "<文章.html>" --title "<标题>" --author "<作者>" \
     --cover "<封面900x383>" --image "<图.png>:{{XXX_IMAGE}}"
   ```
   凭据读 md-to-wechat 技能的 `.env`（默认 `~/.workbuddy/skills/md-to-wechat__skillhub/.env`）；封面与正文图上传后有缓存，重复用同一路径不会重复上传。
4. **两个必踩的坑**：① `.env` 的 `AUTHOR_NAME` 默认是「房小参」，推其他号（如你的另一个号）**必须显式加 `--author`**，否则作者栏串号，会多出一条废草稿；② **推送前一次性跟用户确认标题 + 封面 + 作者**，草稿推错无法撤回，只能多出一条废草稿。

## 四、输出规范

- 每个判定必须"结论 + 依据（含科学解释）+ 化解方案"三件套齐全，不做只下结论不给方法的判断
- 化解方案分三档：**零成本**（调整朝向、收纳刀具、拉窗帘）→ **低成本**（绿植、屏风、灯光、门帘）→ **根本解**（换房）；明确告诉用户哪些只能换房
- 涉及健康的表述用"居住体验下降、心理不适、通风采光受影响"等说法，不承诺祛病改运
- 结论必须能落地：给出实地核实清单（什么时间去、看什么、量什么）
- 输出格式按需：口头研判 / Markdown 报告 / 一图流（可作为公众号、小红书选题，配合楼盘测评内容分发）

## 五、常见组合场景

| 场景 | 处理方式 |
|---|---|
| 单套房源风水研判 | 走完整 Step 1-6 |
| 同小区选楼栋/选楼层 | 重点 Step 2-3，输出楼栋优劣排序（择层为后，楼层在格局之后考虑） |
| 两套房源对比 | 分别走评分卡，横向对比总分与硬伤差异 |
| 只发了户型图 | 重点 Step 4 户型与宅内，外部项标注"待补" |
| 用户已有具体顾虑（"对着路口怎么办"） | 先核实是否构成真煞（够长够直够窄/有无遮挡），再给化解 |
